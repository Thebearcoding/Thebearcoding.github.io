做过 CLIP 和跨模态检索的人进推荐团队，最常接到的活是两类：**给物品做多模态表征**（冷启动、长尾、长序列检索），以及**做 item-to-item（I2I）召回**。两类工作都要面对同一个落差：内容相似不等于用户觉得相似。本篇讲怎样把“内容向量”变成“推荐好用的向量”。

阅读入口：[全覆盖教程](/notes/recsys-llm4rec-guide/)。2025–2026 年各家已上线系统（抖音 SAIL-Embedding、DME、LEMUR，快手 OneRec，小红书 UniNote、IDProxy 等）的细节和线上数字见 [工业界多模态表征](/notes/multimodal-industrial-representation/)。CLIP、SigLIP、难负例与假负例的基础见 [CLIP 与多模态检索](/notes/vision-video-algorithms/)。

## 1. 多模态信号进推荐的三种方式

| 方式 | 做法 | 优点 | 问题 |
|---|---|---|---|
| 冻结特征 | 预训练模型离线编码，向量作为特征输入 | 简单，可复用 | 与推荐目标不一致，也学不动 |
| 对齐后量化 | 先用行为数据微调表征，再量化成可训练的码 | 码可以被推荐梯度更新 | 多一个对齐与量化流程 |
| 端到端 | 多模态大模型直接参与推荐训练或推理 | 上限高 | 成本高，难上线 |

## 2. 冻结向量的两个问题

快手的 QARM（CIKM 2025）把工业界常见的“先预训练多模态模型、再把向量喂给推荐模型”的做法的问题归纳为两点：

**表征不匹配。** 预训练的监督来自图文匹配、分类这类 NLP/CV 任务，推荐模型的监督来自用户行为。两件外观相似的衣服在 CLIP 空间里很近，但一件是爆款、一件无人问津；两本封面毫不相关的书，可能总被同一批人一起买。

**表征学不动。** 向量离线算好存在缓存里，只作为固定输入，推荐模型的梯度传不回去，无法随业务数据更新。

QARM 的两步修正：**物品对齐**，用推荐系统中高相关的物品对（例如召回模型认为高度相关、或用户行为中共现的对）微调多模态模型，让向量分布贴近行为；**量化编码**，把对齐后的向量量化成离散码，下游模型给每个码学一个 embedding，这样“多模态信息”就变成了可训练的 ID 特征。QARM V2 进一步用推理型 LLM 过滤噪声对齐样本，并改进量化方式以减少冲突。

这和跨模态检索里“用视觉证据校准标签监督”的做法是一枚硬币的两面：**一个用内容校准标签，一个用行为校准内容。**

## 3. 自己动手：行为对齐的物品表征

如果要做一个小项目复现这个思路，可以这样设计：

1. **输入**：冻结的 CLIP 图像向量和文本向量，加一个小的 adapter（两层 MLP），只训练 adapter。
2. **正样本**：训练期用户序列里相邻或共同交互的物品对；可以用 Swing 分数筛掉共现太弱的对。只用训练期交互，避免泄漏测试。
3. **负样本**：batch 内负样本 + 少量难负例（内容相似但从未共现）。
4. **假负例**：内容极其相似、又被少数用户同时交互的“负样本”，很可能其实是正样本。可以按内容相似度给它们**软降权**，而不是硬阈值丢弃，并且把三种做法（不处理、硬阈值、软降权）都做成对照。
5. **评估**：I2I Recall@K（给定一个物品，能否召回它的真实共现物品）；按物品交互数分桶，单独报告冷启动桶；再把对齐后的向量喂给语义 ID tokenizer，看下游生成式推荐有没有变化。

## 4. 让多模态大模型输出向量

**NoteLLM-2**（小红书，KDD 2025）研究用多模态大模型做 I2I 表征。他们发现一个现象：把视觉编码器接到 LLM 上端到端微调，模型会**忽视视觉信息**，表征几乎只由文字决定。两个修正：一是多模态上下文学习（mICL），在 prompt 里把视觉内容和文本内容分开，分别压缩，再平衡两者；二是后期融合，把视觉特征直接融合进最终表征，绕过 LLM 对视觉的削弱。

**把 VLM 训成通用 embedding 模型**是 2024 年以后的主线：

- **E5-V**：用 prompt 让多模态大模型把输入“总结成一个词”，取该位置的隐状态作向量；只用文本对训练，也能泛化到图像。
- **VLM2Vec**（ICLR 2025）：取序列最后一个 token 的隐状态作为表征，用对比学习在 MMEB（36 个数据集、四类任务）上训练，支持图文任意组合和任务指令；用 LoRA 即可。
- **UniME**：两阶段。先把一个强文本 embedding 模型的知识蒸馏给多模态大模型的语言部分，蒸馏方式是在一个 batch 内对齐师生两侧相似度分布的 KL 散度，这是一种关系蒸馏，不要求向量本身对齐；再做难负例增强的指令微调，用相似度阈值过滤假负例、取 top-k 难负例。UniME-V2 用多模态大模型当评审，给候选打软匹配分，用来挖难负例并区分假负例。
- **Qwen3-VL-Embedding**：多阶段训练（大规模对比预训练、再用 reranker 蒸馏），支持 Matryoshka 可变维度，有 2B 和 8B 两个尺寸，可作为强基线。

这些方法的共同难点是：**难负例越难，越可能是假负例。** 有监督跨模态检索和哈希方向的研究对这个问题积累很多，面试时能把两边打通，就是差异化。

## 5. I2I 召回：给定一个物品，找相关物品

I2I 的典型用法：用户刚点过物品 A（trigger），召回与 A 相关的物品。王树森课程里的 ItemCF 和 Swing 是基于共现统计的 I2I，见 [召回笔记](/notes/wangshusen-recommender-retrieval/) 第 1–2 节。在此之上：

**item2vec。** 把用户的行为序列当句子、物品当词，用 word2vec 的 skip-gram 训练物品向量。窗口内共现的物品向量接近。

**图嵌入与 EGES。** 把物品共现构成图，用随机游走（DeepWalk、Node2Vec）生成序列再训练。阿里的 EGES 在此基础上加入边信息（类目、品牌、店铺），每种边信息有自己的 embedding，再用可学习的权重融合，缓解新物品没有共现的问题。

**PDN。** 把 I2I 写成两条路径的组合：用户对 trigger 的兴趣（TrigNet）和 trigger 到目标物品的相关性（SimNet），对多个 trigger 求和，兼顾“用户为什么会点这个 trigger”和“trigger 和目标有多像”。

**内容 I2I。** NoteLLM、NoteLLM-2 一类用大模型从内容学 I2I 表征，最大价值在新内容：刚发布的笔记没有共现，却有图文。

**trigger 选择** 往往和模型同样重要：用最近点击的、停留时间长的、还是用户主动搜索的物品当 trigger，会显著改变召回结果。

## 6. 多模态进入长序列

用户的终身行为大多是长尾物品，ID 向量学得差，多模态向量反而可靠。淘宝的 MUSE 用多模态相似度做长序列的 GSU 检索，并在 ESU 中融合 ID 注意力与多模态相似度，见 [序列推荐与长序列](/notes/recsys-sequence-long/) 第 9 节。

## 7. 常见坑

1. **模态不平衡**：文本往往主导，图像信息被忽略。分别报告纯文本、纯图像、融合三种输入的结果，才能说清图像有没有贡献。
2. **缺图**：商品图片链接失效很常见。记录覆盖率，说明缺图物品怎样处理（只在有图子集上比较，或用零向量并加缺失标记）。
3. **共现对泄漏**：用全量交互构造正样本对，测试期的共现就进了训练。只用训练期交互。
4. **只看总体指标**：多模态的价值主要在冷启动与长尾，要按交互数分桶报告。
