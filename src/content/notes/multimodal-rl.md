DeepSeek-R1 证明了只用规则奖励的 RL 能显著提升文本推理能力。2025 年起一批工作把这套方法搬到视觉语言模型上：数学几何题、图表问答、计数、定位。这一篇讲搬过来时哪些东西照旧、哪些东西变了。核心问题只有一个：**RL 带来的提升，到底是模型更会看图了，还是更会利用文字线索猜了？** PPO 与 GRPO 的推导见 [从 RL 基础推到 PPO 与 GRPO](/notes/policy-gradient-ppo-grpo/)，DPO 的推导见 [SFT 与 DPO](/notes/multimodal-sft-lora-dpo/)，长度偏差、熵坍塌等通用问题见 [Agent RL 进阶](/notes/agent-rl-advanced/)。

阅读入口：[多模态学习手册](/notes/multimodal-interview-guide/)。数值算例为教学构造；论文结论注明出处，以原文为准。

## 1. 什么视觉任务有可验证的奖励

规则奖励 RL 的前提是能用程序判断答案对错。视觉任务里有这些：

| 任务 | 奖励怎样算 | 注意 |
|---|---|---|
| 视觉数学（几何、函数图） | 最终答案与标准答案数值相等 | 需要可靠的答案抽取与等价判断（$\frac12$ 与 0.5） |
| 图表 / 文档问答 | 精确匹配或数值容差 | 单位、百分号、千分位 |
| 计数 | 数字相等，或按偏差给部分分 | 部分分要防止“永远猜中间值” |
| 定位 / 检测 | IoU 或匹配后的 F1 | 见 [视觉定位](/notes/multimodal-grounding/) 第 6 节 |
| 选择题 | 选项相等 | 随机猜有 25% 的正确率，见第 3 节 |
| 开放描述 | 没有规则奖励，需要奖励模型或 LLM 裁判 | 回到 RLHF 的范畴 |

再加上**格式奖励**（是否按 `<think>…</think><answer>…</answer>` 输出）。Visual-RFT（arXiv 2503.01785）在分类、检测、定位任务上用 IoU 和准确率作为奖励；VLM-R1（arXiv 2504.07615）在指代表达理解和开放词表检测上训练 Qwen2.5-VL；MM-Eureka（arXiv 2503.07365）专注多模态数学推理，构建了 MMK12 数据集并使用在线过滤与两阶段训练；Vision-R1（arXiv 2503.06749）先用 20 万条多模态思维链数据冷启动，再用 GRPO 加“渐进式思维抑制”训练（先限制思维链长度，再逐步放开）。

## 2. 图像让 rollout 变贵

一个带图的提示通常有上千个视觉 token。GRPO 每个问题要采 $G$ 条回答。

**手算**（教学构造）。提示 1300 token（1200 个视觉 token 加 100 个文本 token），每条回答 500 token，$G=8$。

- rollout 阶段，如果推理引擎不共享前缀，每条回答都重新 prefill 一遍图像：$8\times(1300+500)=14\,400$ 个 token 的计算。共享前缀（vLLM 的前缀缓存或 `n` 参数一次生成多条）时，图像只算一次：$1300+8\times500=5300$。
- 训练阶段，计算 log 概率时每条序列通常都完整前向一次：$8\times1800=14\,400$ 个 token。图像 token 虽然不计损失，却要参与注意力计算和占用激活显存。

所以多模态 GRPO 的显存与时间开销里，**图像 token 占了大头，而它们对梯度没有直接贡献**。常见的优化有：降低训练时的图像分辨率（但会损失细节，影响定位和小字类任务）；冻结视觉编码器，只训练语言模型部分（省掉视觉塔的反向传播）；控制 $G$ 和回答长度。冻结视觉塔是大部分工作的默认选择，它也意味着 RL 主要改变的是“怎样使用视觉特征”，而不是“提取什么视觉特征”。

## 3. 选择题奖励为什么特别吵

很多视觉问答数据是四选一的选择题，奖励天然是 0/1。问题在于随机猜也有 25% 的概率答对。

**手算**（教学构造）。一道模型完全不会的题，它在 4 个选项里随机猜。一组 $G=8$ 条回答：全部猜错的概率 $0.75^8=0.100$，全部猜对的概率 $0.25^8\approx0.00002$，**其余约 90% 的组里有对有错**，于是产生了非零的优势。模型会因为“碰巧猜对”而被强化那条推理链，尽管那条推理与答案毫无关系。这样的梯度纯粹是噪声，而且可能强化“推理和答案不一致”的行为。

**缓解办法**：① 把选择题改写成开放式问答（去掉选项，让模型直接写答案），只保留答案可以被精确匹配的题；② 用初始模型对每道题采样多次，通过率接近 $1/\text{选项数}$ 的题很可能是在猜，过滤掉；③ 检查推理链与最终答案的一致性，例如推理里得出的数值是否等于所选选项。

## 4. 核心问题：提升来自看图还是猜

VLM 有很强的语言先验。很多视觉问答题不看图也能猜个大概（“图中的天空是什么颜色”）。RL 优化的是最终答案的正确率，它并不在意正确率是怎样来的。如果利用文字线索比真正读图更容易拿到奖励，RL 就会强化前者。

**诊断：视觉依赖度。** 同一个评测集，分别用原图和空白图（或无关图）测准确率：

| | 原图准确率 | 空白图准确率 | 差值（视觉依赖） |
|---|---:|---:|---:|
| RL 前 | 0.62 | 0.48 | 0.14 |
| RL 后 | 0.70 | 0.60 | 0.10 |

（教学构造。）总分涨了 8 个点，但空白图准确率涨了 12 个点，视觉依赖反而从 0.14 降到 0.10。**这次 RL 主要提升的是不看图答题的能力**。这种结果在原图准确率上完全看不出来。

**为什么会这样。** 训练数据里很多题的答案能从题干推出：MathVerse（arXiv 2403.14624）指出现有视觉数学基准的题干里塞了过多本应从图中读取的信息，模型可能不看图就推出答案；它因此把 2612 道题各改写成六个版本，逐步把信息从文字移到图里，共 15K 个样本，用来测模型到底有没有读图。另一个原因是长推理链会让模型越来越依赖自己生成的文字：*More Thinking, Less Seeing?*（arXiv 2505.21523）的注意力分析显示，推理链越长，对视觉输入的关注越少，幻觉随之增加；它提出的 RH-AUC 指标衡量感知准确率随推理长度的变化。

**怎样让 RL 真正提升视觉能力。** ① **筛数据**：去掉不看图也能答对的题（用空白图测一遍初始模型），保留必须依赖视觉信息的题；② **对比奖励**：同一题同时用原图和扰动图（遮挡关键区域）生成，奖励只给依赖原图才能答对的情况；③ **感知任务混训**：加入定位、计数这类答案只能从图中得到的任务；④ **每次评测都报告视觉依赖度**，不只报告总分。

## 5. 训练细节上和文本 RL 的差别

- **冷启动**：基座 VLM 的推理格式通常不稳定，直接 RL 时大部分 rollout 格式错误、奖励为 0。多数工作先用少量思维链数据 SFT 冷启动，再做 RL。
- **数据难度过滤**：和 [Agent RL 进阶](/notes/agent-rl-advanced/) 第 4 节一样，通过率为 0 或 1 的题没有学习信号；MM-Eureka 用的就是在线过滤。
- **长度控制**：Vision-R1 观察到冷启动之后模型容易过度思考，推理链过长反而难以优化，所以提出渐进式思维抑制训练（PTST）：先压缩思维链长度，再逐步放开。
- **KL 与参考模型**：参考模型也要处理图像，显存开销翻倍。一些工作去掉 KL 项以节省开销，代价是更容易偏离初始分布。
- **评测**：同时报告 MathVista、MathVerse、MMMU 这类推理基准，以及一个感知类基准（如 [幻觉评测](/notes/multimodal-hallucination-eval/) 里的 POPE），确认推理提升没有以感知退化为代价。

## 6. 多模态 DPO：模型为什么会忽略图像

在没有可验证奖励的开放任务（图像描述、开放问答）上，常用的是偏好优化。RLHF-V（arXiv 2312.00849）让人工逐句修正描述中的幻觉，构造细粒度的偏好对；RLAIF-V（arXiv 2405.17220）用开源模型自动生成偏好反馈，降低标注成本。

**问题：无条件偏好。** 标准 DPO 的偏好对是 $(x,y_w,y_l)$：同一个输入（图 + 问题），一个好回答一个差回答。mDPO（Wang et al., arXiv 2406.11839，EMNLP 2024）指出，如果 $y_w$ 和 $y_l$ 的差别仅从文本就能判断（比如 $y_l$ 语句不通顺、明显更长），模型不需要看图就能学会区分。DPO 的优化于是变成了纯语言的偏好学习，图像条件被忽略。

**mDPO 的修正**有两点。① **图像条件偏好**：额外构造一组对比，回答固定为 $y_w$，图像分别是原图 $m_w$ 和一张被破坏的图 $m_l$（论文的做法是从原图随机裁出不到 20% 的区域，§3.1 与 §4.4 的消融显示这种简单策略效果最好），要求模型在原图下给 $y_w$ 更高的概率：

$$
\mathcal L_{\text{img}}=-\log\sigma\left(\beta\log\frac{\pi_\theta(y_w\mid m_w,q)}{\pi_{\text{ref}}(y_w\mid m_w,q)}-\beta\log\frac{\pi_\theta(y_w\mid m_l,q)}{\pi_{\text{ref}}(y_w\mid m_l,q)}\right).
$$

这一项只有依赖图像才能降低。② **奖励锚点**：DPO 只要求好回答的隐式奖励比差回答高，两者可以同时下降，导致好回答的概率也在降。mDPO 额外要求好回答的隐式奖励为正，防止这种情况。

**和第 4 节是同一个问题。** 无论 RL 还是 DPO，只要训练信号能在不看图的情况下被满足，模型就会走这条捷径。修正方法都是同一个思路：**构造只有看图才能区分的对比**。

## 7. 一个小实验

用 Qwen2.5-VL-3B 做一次小规模 GRPO（教学设计，**不承诺具体结果**），数据取一个几何或图表问答集的几千题：

| 步骤 | 做什么 | 验收 |
|---|---|---|
| 数据 | 用初始模型分别以原图和空白图测一遍；去掉空白图也能答对的题与通过率为 0/1 的题 | 记录过滤前后各剩多少 |
| 训练 | GRPO，$G=8$，冻结视觉塔，奖励 = 答案正确 + 小的格式分 | 奖励、长度、熵曲线 |
| 对照 | 同样设置但不过滤数据 | 两组的原图与空白图准确率 |
| 评测 | 推理基准加一个感知基准 | 视觉依赖度有没有上升；感知有没有退化 |

如果过滤组的视觉依赖度上升而未过滤组下降，这就是一个有因果解释的结论，比单纯报告“准确率涨了几个点”更有说服力。

## 8. 面试常问

**视觉任务的 RL 奖励有哪些？** 视觉数学和图表问答用答案匹配，计数用数值，定位用 IoU，选择题用选项匹配，再加格式奖励；开放描述没有规则奖励，要用奖励模型。

**为什么选择题的奖励有问题？** 随机猜有 $1/\text{选项数}$ 的概率答对，四选一时完全不会的题在 $G=8$ 的组里约 90% 会产生非零优势，强化的是碰巧猜对的推理。可以改写成开放题、过滤通过率接近随机的题、检查推理与答案一致性。

**怎么确认 RL 提升的是视觉能力？** 分别用原图和空白图测，看两者的差值（视觉依赖度）有没有上升。只看原图准确率可能掩盖“更会不看图猜”的情况。

**多模态 DPO 为什么会忽略图像？mDPO 怎么修？** 好坏回答的差别从文本就能判断时，模型不看图也能满足偏好。mDPO 加入固定回答、对比原图与破坏图的条件偏好项，以及让好回答奖励为正的锚点。

**多模态 GRPO 的主要开销在哪？** 图像 token：每条 rollout 都要处理，训练时每条序列都要前向，但不计损失。用前缀共享、冻结视觉塔、控制分辨率和组大小来降开销。

## 闭卷验收

不看资料列出六类视觉任务的奖励计算方式和注意点；说出 Visual-RFT、VLM-R1、MM-Eureka、Vision-R1 各自的侧重；手算 $G=8$ 时有无前缀共享的 rollout token 数和训练前向 token 数，解释为什么多数工作冻结视觉塔；手算四选一随机猜时一组 8 条全错、全对、有对有错的概率，并解释为什么这是噪声；对给定的 RL 前后原图与空白图准确率计算视觉依赖度并下结论；说出让 RL 真正提升视觉能力的四种方法；列出多模态 RL 与文本 RL 在训练细节上的五点差别；写出 mDPO 的图像条件偏好项并解释奖励锚点的作用；最后设计一个包含数据过滤、对照组和视觉依赖度评测的小实验。
