问模型“图里左边穿蓝衣服的人在做什么”，它答得出来，不代表它知道“左边穿蓝衣服的人”在哪里。定位（grounding）要求模型把语言明确对应到图像中的一个区域，输出可以被程序检查的坐标。这一篇讲定位任务的几种形式、框在模型里怎样表示、坐标在预处理前后怎样换算，以及怎样评估和训练。ViT 的 patch 和视觉 token 的来龙去脉见 [为什么图像和视频能够进入语言模型](/notes/vision-video-algorithms/)，时间维度上的定位见 [视频理解](/notes/multimodal-video-understanding/)。

阅读入口：[多模态学习手册](/notes/multimodal-interview-guide/)。数值算例为教学构造；模型细节以对应技术报告和官方代码为准。

## 1. 几种定位任务

| 任务 | 输入 | 输出 | 典型数据集 |
|---|---|---|---|
| 指代表达理解（REC） | 图 + 一句唯一指向某个物体的描述 | 一个框 | RefCOCO / RefCOCO+ / RefCOCOg |
| 短语定位 | 图 + 一段描述，含多个名词短语 | 每个短语一个或多个框 | Flickr30k Entities |
| 开放词表检测 | 图 + 任意类别名列表 | 所有匹配物体的框 | LVIS、ODinW |
| 指代分割 | 图 + 描述 | 像素级掩码 | RefCOCO 的分割标注 |
| 定位式描述 | 图 | 描述文本，其中的名词带框 | Kosmos-2 的 GRIT |

RefCOCO 的三个版本差别值得记住：RefCOCO 的描述里允许方位词（“左边的人”）；RefCOCO+ 禁止方位词，迫使模型依靠外观属性；RefCOCOg 的描述更长、更复杂。三者常常一起报告，因为它们分别考察空间关系、外观辨别和复杂语言理解。

**REC 和检测的区别**在于唯一性：检测要找出所有“人”，REC 要从多个人中找出被描述的那一个。图里只有一个人时，REC 退化成检测；有五个穿着相似的人时，必须理解“左边第二个、拿着伞的”。

## 2. 框怎样表示：三种做法

**回归头。** 传统检测器和 Grounding DINO（arXiv 2303.05499）这类专用模型，在 Transformer 的输出上接一个小网络，直接回归四个连续数值（中心点和宽高，归一化到 $[0,1]$），用 L1 损失加 GIoU 损失训练。精度高，但需要专门的结构，不能和文本生成统一。

**位置 token。** Kosmos-2（arXiv 2306.14824）把图像划成 $32\times32$ 的网格，每个格子对应词表里一个新增的 token，一个框用左上角和右下角两个格子的 token 表示。好处是一个框只占两个 token；坏处是精度受网格大小限制，并且要扩充词表。

**坐标写成文本。** Shikra（arXiv 2306.15195）以及 Qwen-VL 系列直接让模型生成数字字符串，例如 `(123,456),(789,640)`。不改结构、不扩词表，和文本生成完全统一，是目前通用 VLM 的主流做法。代价是：数字被当作普通 token 用交叉熵训练，预测 `499` 和 `500` 的损失与预测 `499` 和 `900` 一样大，模型对“差一点”和“差很多”没有区分；而且若分词器把数字逐位切开（Qwen 系列如此），一个框加上括号逗号要二十个 token 左右。

## 3. 坐标系：归一化还是绝对像素

**Qwen2-VL**：坐标归一化到 $[0,1000)$ 的整数，用 `<|box_start|>(x1,y1),(x2,y2)<|box_end|>` 包裹，被指代的文本用 `<|object_ref_start|>…<|object_ref_end|>` 包裹。归一化的好处是与图像分辨率无关。

**Qwen2.5-VL**：改用**基于输入图像实际尺寸的绝对坐标**（技术报告 arXiv 2502.13923 §2）。理由是模型本来就以原生分辨率输入图像，绝对坐标让它能感知物体的真实大小，而不是只知道相对比例；输出格式也改成了 JSON，如 `{"bbox_2d": [x1, y1, x2, y2], "label": "..."}`。

**陷阱：这里的“实际尺寸”是预处理之后的尺寸。** Qwen2.5-VL 会把图像缩放到宽高都是 28 的倍数（每个视觉 token 对应 $28\times28$ 像素，即 14 像素的 patch 再做 $2\times2$ 合并），并受 `min_pixels`、`max_pixels` 约束。模型输出的坐标在缩放后的坐标系里，画回原图时必须换算。

**手算**（教学构造）。原图 $1920\times1080$，假设预处理后为 $1288\times728$，视觉 token 数为 $(1288/28)\times(728/28)=46\times26=1196$。缩放系数 $s_x=1288/1920=0.6708$，$s_y=728/1080=0.6741$，两个方向并不完全相同。模型输出框 $(644,364,800,500)$，换回原图：

$$
(644/0.6708,\ 364/0.6741,\ 800/0.6708,\ 500/0.6741)=(960,\ 540,\ 1192.5,\ 741.8).
$$

如果忘了换算，直接把 $(644,364,800,500)$ 画在原图上，框会偏到左上方，IoU 可能接近 0。如果按 Qwen2-VL 的千分位格式表示同一个框，是 $(500,500,621,687)$。**训练数据和推理代码必须用同一个坐标约定**：用 Qwen2-VL 格式的数据去微调 Qwen2.5-VL，或者反过来，都会得到系统性的错位。这是复现时最常见的 bug。

## 4. 评估：IoU、GIoU 与 Acc@0.5

**IoU**（交并比）：

$$
\mathrm{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}.
$$

**手算**（教学构造）。预测框 $A=(50,40,150,140)$，真值框 $B=(100,90,200,190)$，格式为 $(x_1,y_1,x_2,y_2)$，都是 $100\times100$。交集是 $(100,90,150,140)$，面积 $50\times50=2500$；并集 $10000+10000-2500=17500$；$\mathrm{IoU}=2500/17500=0.143$。两个框各自错开了半个边长，IoU 就只剩 0.14，远低于常用的 0.5 阈值。

**Acc@0.5**：REC 的标准指标，IoU $\ge0.5$ 算对，报告正确比例。它是一个阶跃函数：IoU 为 0.49 和 0.01 一样算错。有时也报告 Acc@0.75 或平均 IoU 来反映精细程度。

**GIoU**（Rezatofighi et al., CVPR 2019）：IoU 在两框不相交时恒为 0，没有梯度告诉模型“该往哪边移”。GIoU 引入同时包住两框的最小框 $C$：

$$
\mathrm{GIoU}=\mathrm{IoU}-\frac{|C|-|A\cup B|}{|C|}.
$$

上例中 $C=(50,40,200,190)$，面积 22500，$\mathrm{GIoU}=0.143-(22500-17500)/22500=0.143-0.222=-0.079$。两框离得越远，$C$ 中的空白越多，GIoU 越接近 $-1$，即使不相交也能提供方向信号。回归头训练用 $1-\mathrm{GIoU}$ 作为损失；生成坐标文本的 VLM 不能直接用它求梯度，但可以在 RL 里把它当奖励（第 6 节）。

## 5. 数据从哪里来

定位数据的标注成本很高，主流 VLM 的定位能力主要来自三类数据：

- **人工标注的定位数据集**：RefCOCO 系列、Visual Genome 的区域描述、Flickr30k Entities。质量高但规模有限，而且集中在 COCO 的 80 类常见物体上。
- **检测数据转写**：把 Objects365、OpenImages 等检测数据转成“找出图中所有的 X”格式的问答。规模大，但语言简单。
- **自动生成**：用检测器加名词短语抽取，给图文对中的名词自动配框，例如 Kosmos-2 构建的 GRIT。规模最大，但有噪声（框错、短语对错物体）。

**评测污染**：RefCOCO 的图片来自 COCO 训练集，很多 VLM 的预训练数据里包含 COCO。测试集图片可能在训练中见过（虽然描述不同）。报告 RefCOCO 分数时，最好同时报告在一个新数据集上的结果。

## 6. 用强化学习训练定位

定位天然适合 RL：IoU 是可计算的奖励，不需要训练奖励模型。Visual-RFT（arXiv 2503.01785）和 VLM-R1（arXiv 2504.07615）等工作用 GRPO 训练 VLM 做定位和检测，奖励通常是 **IoU 奖励加格式奖励**（输出能否被解析成合法的框）。

**为什么 RL 可能比 SFT 好。** SFT 用交叉熵逐个数字地拟合标注坐标，`499` 和 `900` 的错误被同等对待。RL 直接优化 IoU，差一点的预测拿到较高的奖励，差很多的预测拿到较低的奖励，奖励形状与真正的目标一致。另外，RL 用的是模型自己采样的输出，能修正“推理时的分布与训练标注不一致”的问题。

**手算：同一题的 GRPO 优势**（教学构造）。组大小 4，四次输出的 IoU 分别为 0.72、0.55、0.14、0.00（最后一个格式错误，无法解析）。若奖励直接取 IoU：均值 0.3525，四个优势的符号是 $(+,+,-,-)$，IoU 为 0.55 的那次也被强化了。若奖励取 Acc@0.5 式的 0/1：$(1,1,0,0)$，两种奖励给出相同的排序，但连续奖励能区分 0.72 和 0.55。

**要注意的。** ① **奖励黑客**：如果只奖励 IoU 而不惩罚多框，模型可能输出一个覆盖大半张图的框（对大物体能拿到不低的 IoU）；多目标检测任务要用匹配后的指标（如 F1 或 mAP 式奖励）。② **坐标约定**：奖励函数必须和模型的坐标系一致，第 3 节的换算错误在 RL 里会让奖励全部接近 0，训练不动。③ **格式奖励不要太大**：否则模型只学会输出合法的框，不关心位置。

## 7. 常见失败与诊断

| 现象 | 可能原因 | 怎样检查 |
|---|---|---|
| 框整体偏向左上或右下 | 坐标系约定错误，或缩放后没有换算回原图 | 在几张图上把预测框画出来 |
| 方位词（左/右）经常错 | 训练中方位数据少；水平翻转增强让方位标签失效 | 分别在 RefCOCO 与 RefCOCO+ 上看差距 |
| 小物体定位差 | 输入分辨率太低，物体只占一两个视觉 token | 按物体面积分桶统计 Acc@0.5 |
| 多个相似物体时选错 | 属性理解不足，只按类别定位 | 构造同类多实例的测试集 |
| 描述的物体不存在时仍然输出框 | 训练数据里每个问题都有答案 | 加入“不存在”的负样本测试 |

最后一条和 [多模态幻觉](/notes/multimodal-hallucination-eval/) 直接相关：模型对不存在的物体给出坐标，是一种可以被精确检测的幻觉。

**数据增强的坑**：水平翻转是视觉任务中最常用的增强，但它会让“左边的人”变成右边的。定位训练里做翻转时，必须同时交换描述中的“左”和“右”，以及框的 $x$ 坐标。

## 8. 面试常问

**VLM 输出坐标有哪几种方式？各有什么优缺点？** 回归头（精度高，需要专门结构）、位置 token（一个框两个 token，精度受网格限制、需扩词表）、坐标文本（不改结构、和生成统一，但交叉熵对数值距离不敏感、占 token 多）。

**Qwen2-VL 和 Qwen2.5-VL 的坐标有什么不同？** 前者归一化到 0–1000，后者用基于预处理后图像尺寸的绝对像素坐标、JSON 格式输出。用后者时要把坐标按缩放系数换回原图；两种格式的数据不能混用。

**IoU 和 GIoU 的区别？为什么要 GIoU？** IoU 在两框不相交时恒为 0，没有梯度；GIoU 减去最小外接框中空白区域的比例，不相交时也能提供方向信号，取值在 $(-1,1]$。

**为什么 RL 适合定位任务？** IoU 是可计算的连续奖励，奖励形状与目标一致；SFT 的交叉熵对数字的远近不敏感。要防止大框黑客、保证奖励与坐标约定一致。

**模型在小物体上定位差，怎么改进？** 先确认是分辨率问题（按面积分桶统计）；提高输入分辨率或对局部区域裁剪放大后再定位；增加小物体的训练数据。
