[为什么图像和视频能够进入语言模型](/notes/vision-video-algorithms/) 第 6–7 节讲了时间建模为什么不等于逐帧看过、采帧和分辨率怎样共用预算；[Prefill、Decode 与视频 token](/notes/prefill-decode-video-tokens/) 讲了视频 token 怎样影响首字延迟和 KV 缓存。这一篇在此基础上往前走：具体的 token 账怎样算、几种压缩方案的取舍、真实时间怎样进入模型、怎样让模型输出“事件发生在第几秒”，以及小时级的长视频怎么办。最后讲视频评测中最常见的陷阱。

阅读入口：[多模态学习手册](/notes/multimodal-interview-guide/)。数值算例为教学构造；模型细节以对应技术报告为准。

## 1. 先算 token 账

以 Qwen2.5-VL 的做法为例（技术报告 arXiv 2502.13923）：视觉编码器的 patch 是 $14\times14$，空间上相邻 $2\times2$ 个 patch 合并成一个 token，所以每个 token 对应 $28\times28$ 像素；时间上，相邻两帧合成一个 3D patch（时间 patch 大小为 2）。于是：

$$
\text{视觉 token 数}=\frac{T}{2}\times\frac{H}{28}\times\frac{W}{28},
$$

其中 $T$ 是采样帧数，$H\times W$ 是缩放后每帧的分辨率。

**手算**（教学构造）。一段 60 秒的视频，按 2 fps 采样得到 $T=120$ 帧，每帧缩放到 $448\times252$。每两帧一组共 60 组，每组 $(448/28)\times(252/28)=16\times9=144$ 个 token，合计 $60\times144=8640$ 个视觉 token。同样设置下，10 分钟的视频是 86 400 个 token。

如果视觉 token 预算是 16 384，每组 144 个 token，最多 113 组即 226 帧。10 分钟的视频只能每 2.65 秒采一帧，或者保持 2 fps 而把每帧分辨率压到更低。**帧率、分辨率和时长三者共用一个预算**，这是视频理解所有设计取舍的出发点。

## 2. 短事件会不会被采样漏掉

均匀采样时帧间隔为 $\Delta$。一个持续 $d$ 秒的事件（$d<\Delta$），如果开始时刻相对采样网格是随机的，没有任何一帧落在事件内的概率是 $1-d/\Delta$。

手算：10 分钟视频均匀采 32 帧，$\Delta=600/32=18.75$ 秒；一个持续 3 秒的动作（“把钥匙放进口袋”）被完全漏掉的概率是 $1-3/18.75=0.84$。改成 1 fps，间隔 1 秒，3 秒的事件至少会被采到 2 帧。

这说明两件事。① 关于短事件的问题，32 帧的模型多半是在**猜**，而不是“没看清”。评测时要知道答案所需的证据有没有被采进来。② 均匀采样不是唯一选择：可以根据问题选帧（先用便宜的方法，例如 CLIP 相似度，在所有帧里找和问题相关的片段，再密集采样那一段），这正是长视频方法的核心思路（第 6 节）。

## 3. 压缩：把每帧的 token 变少

每帧 token 太多时，有几种压缩方式：

| 方法 | 做法 | 代价 |
|---|---|---|
| 空间池化 | 对每帧的特征图做 $2\times2$ 或更大的平均池化 | 小物体和文字细节丢失 |
| 时间合并 | 相邻帧合成一个 token（Qwen 的时间 patch 2） | 快速动作的细节丢失 |
| Q-Former / 重采样器 | 用固定数量的可学习查询从每帧特征中抽取信息（BLIP-2、Video-LLaMA） | 查询数决定上限，难以保留空间位置 |
| SlowFast | 少量帧保留高分辨率（慢路径），大量帧用低分辨率（快路径） | 两条路径的配比需要调 |
| token 合并 / 剪枝 | 按相似度合并相邻帧中重复的 token（静态背景） | 实现复杂；可能误合并 |

**相邻帧高度冗余**是压缩的依据：固定镜头下背景几乎不变，真正变化的只有运动的部分。token 合并类方法（如在 ViT 层间合并相似 token）就是利用这一点。但冗余程度依赖视频内容：一段静态讲座和一段运动比赛，可以压缩的程度相差很大。按内容自适应地分配 token，比固定的压缩率更合理。

## 4. 真实时间怎样进入模型

如果只给模型帧的序号（第 1、2、3……帧），它无法知道两帧之间隔了多久：同样是第 10 帧，在 1 fps 采样下是第 10 秒，在 0.1 fps 下是第 100 秒。回答“这个动作持续了多久”“事件发生在第几秒”时，模型必须知道真实时间。

**Qwen2-VL 的 M-RoPE**（arXiv 2409.12191）把旋转位置编码拆成三个分量：时间、高、宽。文本 token 三个分量取相同的值，退化为普通的一维 RoPE；视觉 token 的时间分量是帧组序号，高宽分量是它在特征图上的行列。RoPE 本身的原理见 [Transformer 一章](/notes/transformer-attention-rope-gqa/)。

**Qwen2.5-VL 的改进**：把时间分量的位置 ID 与**绝对时间**对齐，而不是与帧序号对齐（技术报告 §2.1.3）。这样，不论采样率是多少，相邻时间 ID 之间的间隔都对应相同的真实时长，模型通过时间 ID 的间隔就能感知采样快慢和事件节奏。训练时使用动态帧率采样，让模型见过各种采样密度。

**另一种做法是写进文本**：在每帧的视觉 token 前插入时间戳文本，如 `<t=12.5s>`。实现简单、与模型结构无关，代价是每帧多几个 token，而且模型要学会把文本数字和画面内容对应起来。

## 5. 时间定位：输出“在第几秒”

**任务**：给一段视频和一句描述（“男人打开冰箱”），输出事件的开始和结束时间。典型数据集有 Charades-STA、ActivityNet Captions、QVHighlights。

**输出方式**与 [视觉定位](/notes/multimodal-visual-grounding/) 第 2 节一一对应：可以回归连续的时间值，可以用离散的时间 token，也可以直接生成文本 `12.0 - 20.0 seconds`。通用视频 LLM 大多采用最后一种，前提是模型对真实时间有感知（第 4 节）。

**评估**：时间上的 IoU（tIoU）：

$$
\mathrm{tIoU}=\frac{|[s_p,e_p]\cap[s_g,e_g]|}{|[s_p,e_p]\cup[s_g,e_g]|}.
$$

手算：预测 $[12.0,20.0]$ 秒，真值 $[15.0,25.0]$ 秒，交集 $[15,20]$ 为 5 秒，并集 $[12,25]$ 为 13 秒，$\mathrm{tIoU}=5/13=0.385$。常用指标是 R@1, IoU=0.5（排第一的预测 tIoU 至少 0.5 的比例）和 IoU=0.7，以及平均 tIoU（mIoU）。

**时间定位的精度上限由采样决定。** 如果 1 fps 采样，模型看到的最小时间单位就是 1 秒；如果 32 帧覆盖 10 分钟，每帧间隔近 19 秒，精确到秒的定位是不可能的。读论文的定位分数时，要看它用了多少帧、多少 fps。

## 6. 长视频：三条路线

小时级的视频，即使 1 fps 也是 3600 帧，按每帧几十个 token 计算也有十几万个 token。目前有三条路线：

**① 扩大上下文。** 把上下文扩展到几十万甚至上百万 token，让模型直接“看完”。LongVA（arXiv 2406.16852）把语言模型的长上下文能力迁移到视觉，能处理 2000 帧、超过 20 万个视觉 token；长上下文版本的商用模型也属于这一类。优点是不丢信息；缺点是 prefill 成本高，而且上下文越长，模型对中间部分的利用越差。

**② 检索后再看。** 先用便宜的方法（CLIP 特征、字幕、粗粒度描述）建一个片段索引，根据问题检索出最相关的几个片段，再用 VLM 细看这些片段。本质上是把 [RAG](/notes/agent-rag/) 用在视频上。优点是成本可控；缺点是检索失败时答案必错，而且需要综合全片的问题（“这部电影的主题是什么”）不适合检索。

**③ Agent 式探索。** 让模型像人一样浏览：先看低帧率的概览，决定跳到哪里细看，可以多次往返。VideoAgent（arXiv 2403.10517）是这一类的代表：以 LLM 为中心 Agent，把 VLM 和 CLIP 当工具，迭代地决定还要看哪些帧，在 EgoSchema 和 NExT-QA 上评测。灵活，但调用次数多、延迟高，策略本身需要训练或精心设计。

**记忆压缩**是贯穿三条路线的思路：把看过的片段压缩成文本描述或少量 token 存起来，后续只保留摘要。代价与 [Agent 记忆压缩](/notes/agent-planning-memory/) 第 7 节相同：细节一旦被压缩掉就找不回来。

## 7. 评测：识破“看一帧就能答”

| 基准 | 侧重 |
|---|---|
| MVBench | 20 类单帧无法解决的视频任务，由静态图像任务“动态化”改写而来（动作顺序、计数、方向等） |
| Video-MME | 900 个视频、2700 道多选题（每个视频 3 道），时长 11 秒到 1 小时，分短、中、长三档；有无字幕两种设置 |
| EgoSchema | 取自 Ego4D 的第一人称视频，5000 多道人工整理的五选一题，每题对应一段 3 分钟的片段 |
| NExT-QA | 因果动作推理、时序动作推理和场景理解三类问答，有多选与开放两种形式 |
| TempCompass | 专门测时间感知，分动作、速度、方向、属性变化、事件顺序五个方面；用倒放、拼接等方式构造对照视频 |
| Charades-STA / QVHighlights | 时间定位 |

**最大的陷阱：静态捷径。** 很多视频问答题其实看一帧就能答（“视频里的人穿什么颜色的衣服”），甚至不看视频只看问题和选项就能猜对。这类题的高分说明不了时间理解能力。三个诊断实验：

1. **单帧对照**：只给模型中间一帧（或随机一帧），看准确率下降多少。下降很少的题不需要时间信息。
2. **打乱帧序**：把帧随机打乱后再测。如果准确率几乎不变，模型没有利用时间顺序。对于“先做了什么”这类题，打乱后准确率应该降到接近随机。
3. **无视觉对照**：只给问题和选项，看能猜对多少，衡量语言先验的贡献。

**字幕的影响**：Video-MME 同时报告有无字幕的结果，摘要的结论是字幕和音频能显著提升视频理解的分数。这说明字幕本身携带了大量答题信息，加字幕后的高分不能全部算作视觉能力。分析模型的视觉能力时，要看无字幕的分数。

## 8. 一个小实验：测你的模型是否在用时间

用一个开源视频 LLM 和 MVBench 或 TempCompass 的子集，跑下面这张表（教学设计，**不承诺具体结果**）：

| 设置 | 预期现象 | 能说明什么 |
|---|---|---|
| 正常输入 | 基线 | — |
| 只给中间一帧 | 时间类题目大幅下降，属性类题目基本不变 | 哪些题真正需要时间 |
| 帧序打乱 | 顺序类题目降到接近随机 | 模型是否利用了顺序 |
| 帧序倒放 | “先后”题的答案应该反转 | 模型是否理解方向 |
| 无视觉 | 接近随机才说明题目不靠语言先验 | 题目本身的质量 |
| 帧数 8 / 16 / 32 / 64 | 短事件题随帧数提升 | 采样覆盖率的影响 |

每一项都写成“因为……所以……”的结论，并配上 3 个具体样例。这张表本身就是面试时讲视频项目的好材料：它展示的是你对“模型到底学到了什么”的判断方法，而不只是一个分数。

## 9. 面试常问

**视频 LLM 的视觉 token 数怎么算？** 帧数除以时间 patch 大小，乘以每帧的空间 token 数（高宽各除以 28，以 Qwen2.5-VL 为例）。60 秒、2 fps、$448\times252$ 是 8640 个。帧率、分辨率、时长共用预算。

**Qwen2.5-VL 怎样处理时间？** M-RoPE 把位置编码拆成时间、高、宽三个分量；2.5 版把时间分量与绝对时间对齐，配合动态帧率训练，模型能从时间 ID 间隔感知真实时长。

**长视频有哪几种处理方式？** 扩大上下文直接看完；先检索相关片段再细看；Agent 式多次浏览。另有记忆压缩贯穿其中。各自的代价是成本、检索失败、延迟。

**怎么判断模型真的理解了时间？** 单帧对照、打乱帧序、倒放、无视觉对照。时间类题目在打乱后应该降到接近随机；如果不变，模型在走静态捷径。

**为什么 32 帧的模型答不好短动作的问题？** 10 分钟 32 帧，间隔近 19 秒，3 秒的动作有 84% 的概率一帧都采不到。证据不在输入里，模型只能猜。
