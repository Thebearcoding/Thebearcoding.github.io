“LLM4Rec”这个词覆盖的东西太多：有人用 LLM 写物品描述，有人让 LLM 直接回答“用户会不会喜欢”，有人只借 Transformer 的架构从头训练。面试时被问到，先把它们分开。本篇按**LLM 在链路中的位置**整理，每一类回答三个问题：物品怎样进入模型，训练信号是什么，线上成本在哪里。

阅读入口：[全覆盖教程](/notes/recsys-llm4rec-guide/)。语义 ID 的细节见 [语义 ID](/notes/recsys-semantic-id/)，SFT、DPO、GRPO 的基础见 [SFT 与 DPO](/notes/multimodal-sft-lora-dpo/) 和 [策略梯度与 PPO/GRPO](/notes/policy-gradient-ppo-grpo/)。

## 1. 先画一张表

| 用法 | LLM 做什么 | 代表 | 线上通常跑什么 |
|---|---|---|---|
| 编码器 | 把物品或用户的文本、图像编码成向量 | NoteLLM、HLLM | 向量离线算好，线上只做检索 |
| 推荐器（文本） | 读 prompt，回答“是否喜欢”或输出物品名 | P5、TALLRec、LLaRA | 多用于研究或低 QPS 场景 |
| 生成式推荐器 | 直接生成物品的语义 ID | LC-Rec、PLUM、OneRec、MiniOneRec、OpenOneRec | 专门训练的生成模型 + 约束解码 |
| 老师与评审 | 生成标注、做奖励模型、蒸馏小模型 | 各类蒸馏与 LLM-as-judge | 蒸馏后的小模型 |
| 数据与内容 | 生成文案、补全描述、领域后训练 | 广告文案生成、SNS 后训练 | 生成结果或领域模型 |

另有一类常被归入生成式推荐，但不用 LLM 权重：**HSTU、MTGR 这类“推荐专用的大序列模型”**，借的是架构和训练方式，见 [排序模型的 scaling](/notes/recsys-scaling-ranking/)。

## 2. LLM 当推荐器：物品怎样写进 prompt

**P5**（2022）把评分预测、序列推荐、解释生成等任务都写成文本到文本，用 T5 统一训练。物品用数字 ID 表示，例如 “item_7391”，分词后变成几个子词。问题在于数字 ID 的子词切分没有语义，“7391”和“7392”共享子词却毫无关系。

**TALLRec**（2023）把任务简化为二分类：给出用户喜欢和不喜欢的物品标题，问“用户会喜欢这个吗，回答 Yes 或 No”，用 LoRA 微调 LLaMA。它说明了少量推荐数据就能让 LLM 学会这种判断，但只能逐个打分，不能从全库检索。

**LLaRA**（2023）注意到纯文本丢掉了协同信号，于是把传统序列推荐模型（如 SASRec）学到的物品 embedding 投影到 LLM 的 token 空间，和物品标题一起放进 prompt；训练时用课程学习，先只用文本，再逐步引入这种混合表示。

这一类的共同局限：每个候选都要跑一次 LLM，或者只能在很小的候选集里选，难以直接用于全库召回。

## 3. LLM 当编码器：最容易落地

**NoteLLM**（小红书，2024）用一个压缩提示把一篇笔记压缩成一个特殊 token 的隐状态，作为笔记向量；训练信号来自用户行为中的共现笔记对，用对比学习拉近，同时让模型生成话题标签作为辅助任务。线上只需要离线算向量，做 item-to-item 召回。多模态的后续工作 NoteLLM-2 见 [多模态推荐](/notes/recsys-multimodal-i2i/)。

**HLLM**（字节，2024）用两层 LLM：物品 LLM 读物品文本、输出物品向量；用户 LLM 读用户历史的物品向量序列，预测下一个物品的向量。两层一起训练。它把“物品理解”和“用户兴趣”分开，物品向量也可以单独拿去用。

**为什么容易落地**：编码是离线的，线上只有向量检索，不增加请求延迟。面试时被问“LLM 怎样在推荐里真正上线”，这是最稳的回答。

## 4. 生成式推荐器：语义 ID 进入词表

把语义 ID 当成新 token 加进 LLM 的词表，模型就能像写文字一样写出物品。难点是 **LLM 不认识这些新 token**，需要对齐。

**LC-Rec**（2023）用残差量化给物品分配 SID，并在量化时约束分配均匀以减少冲突；然后设计多种对齐任务一起微调：根据历史预测下一个物品的 SID、在物品标题和 SID 之间互相翻译、从用户历史推断意图等。让模型在“文本世界”和“SID 世界”之间建立映射。

**PLUM**（YouTube，2025）在工业规模上做类似的事：先用 SID 和领域数据对预训练语言模型做**继续预训练**，让模型熟悉 SID；再针对生成式召回做微调。

**OpenOneRec**（快手，2025 年底开源）把物品称为 itemic token，经过物品-文本对齐、联合预训练、SFT、在线策略蒸馏与强化学习，发布了基于 Qwen3 的 1.7B 和 8B 模型，以及覆盖 8 类任务的评测基准 RecIF-Bench。**OneRec-Think** 进一步让模型在生成物品前先输出文字推理。

对齐的经验可以概括为两点：一是要有 SID 与文本的双向任务，不能只训练“历史 → 下一个 SID”；二是继续预训练的数据配比决定了模型是否会遗忘通用语言能力。

## 5. 端到端生成：OneRec 与 MiniOneRec

**OneRec**（快手，2025）的目标更激进：用一个生成模型替代“召回 + 粗排 + 精排”的级联。它用平衡 K-means 生成语义 ID；编码器读用户历史，解码器（带 MoE）一次生成一个会话里要展示的多个物品；再用奖励模型对生成结果打分，构造偏好对，用 DPO 类方法迭代对齐。后续的 **OneRec 技术报告**与 **OneRec-V2** 描述了在快手主场景的部署，以及用强化学习和奖励系统进一步优化。

**MiniOneRec**（2025）是第一个完整开源这条流程的框架，三个阶段：

1. **SID 构建**：用冻结的文本编码器编码物品标题与描述，三层 RQ-VAE 量化（也支持 RQ-KMeans）。
2. **SFT**：在 Qwen 骨干上训练“历史 SID 序列 → 下一个 SID”，同时加入语言与 SID 互相对齐的任务，让 LLM 的世界知识进入 SID 空间。
3. **推荐导向的 RL**：用 GRPO。每个 prompt 用**约束 beam search** 生成一组不重复、合法的候选（而不是随机采样，因为动作空间是有限的物品集合）；奖励由“是否命中”与“排名感知”的项组成，对高概率却错误的物品惩罚更重，也可以加入协同过滤分数；组内归一化奖励，并用 KL 惩罚保持接近参考模型。

论文在 Amazon 评论数据上从 0.5B 到 7B 的 Qwen 骨干训练，报告训练和验证损失随模型变大持续下降，作为“生成式推荐在公开数据上也有 scaling 趋势”的证据。

**为什么用约束 beam search 做 RL 采样。** GRPO 需要同一个 prompt 的一组回答。如果随机采样，很多样本会重复或生成非法 SID，组内方差小、信号弱。约束 beam search 保证每条都合法且不同，组内比较更有信息量。这是推荐场景和数学推理场景做 RL 最不一样的地方之一。

## 6. 不扩词表的选择

扩词表要大量高质量数据才能让 LLM 学会新 token。另一类做法是**完全使用 LLM 原生词表**：给每个物品生成一组规范化的自然语言关键词作为标识，生成时允许近似匹配，再映射回真实物品。也有工作反过来扩展分词器、加入高频领域词，以缩短序列、提高推理效率，并保证新分词器切出来的 token 数不多于原来。两种思路的共同点是：**表示层不是固定的，要和任务的分布对齐**。

## 7. LLM 当老师、评审和数据源

**蒸馏。** 让大模型在离线数据上打分或生成解释，用来训练线上的小模型；或者用 LLM 补全物品与用户画像的文字描述，作为特征输入传统模型。

**内容生成与 CTR 对齐。** 广告文案、推送标题这类内容可以用 LLM 生成。仅靠 SFT，生成的文案只是“像历史文案”；要让它点击率更高，就要把 CTR 变成训练信号：用历史 A/B 中的高低 CTR 文案构造偏好对做 DPO，并按 CTR 差值或置信度给样本加权；或者训练一个预测 CTR 相对高低的奖励模型，再做 PPO/GRPO。风险是 **reward hacking**：模型学会讨好奖励模型（夸张、标题党），而不是真正提高用户满意度。需要人工审核、规则约束和线上实验兜底。

**领域后训练。** 社交平台语料里有大量新词、缩写和社区黑话，通用模型分布不匹配。小红书 RedOne 的流程是继续预训练 → 多任务 SFT → 偏好优化；RedOne 2.0 改为先用 RL 探索、发现薄弱任务，再用 SFT 有针对性修补，最后再用 RL 精炼，以减少“学了新任务、忘了通用能力”的跷跷板效应。

## 8. 生成式推荐是不是伪范式

这是面试里很好的开放题，正反两面都要能讲。

**支持者的理由。** 词表从千万级 ID 缩到几千个 SID token，参数可以花在序列模型上，出现了随规模提升的趋势；相似物品共享前缀，长尾和新物品得到泛化；一个模型统一召回和排序，减少级联之间目标不一致的问题；还能自然接入 LLM 的世界知识和推理。

**质疑者的理由。** 不少论文的基线偏弱：SASRec 用 BCE 加一个负样本，换成全库 softmax 后差距大幅缩小（见 [序列推荐](/notes/recsys-sequence-long/)）。SID 由内容决定，并不天然包含协同信号；生成时每步只有前缀约束，召回数量受 beam 大小限制，成本随 beam 线性增长。还有一些所谓“生成式”的收益其实来自更多特征、更大的序列长度或更好的训练配方。

**一个平衡的回答。** 生成式推荐的价值，更多在于**把推荐模型改造成可以 scaling 的结构**和**统一多阶段目标**，而不是“生成”这个动作本身。评价一项工作时问三件事：基线是否用了同等的损失和负样本，增益随规模是否持续，线上成本（QPS、延迟、MFU）是否可接受。

## 9. 选型速查

| 你的约束 | 建议 |
|---|---|
| 要尽快上线、不加延迟 | LLM 当编码器，离线产出物品向量或 SID 特征 |
| 有大量内容、冷启动重 | SID 当特征，或多模态编码器 + 行为对齐 |
| 想做研究、算力有限 | MiniOneRec 一类开源框架，小模型 + 公开数据 |
| 有工业级算力和团队 | 端到端生成（OneRec 一类），但要配奖励系统和线上兜底 |
| 内容生成 | SFT + CTR 偏好对齐，重点防 reward hacking |
