CLIP 把图像和文本各自编码成一个向量，算余弦相似度就能检索。它有两个硬限制：图和文必须分开编码，查询里不能同时带图和字（“把这张图里的沙发换成红色的商品”）；而且没有“任务”的概念，同一张图用于分类、检索还是定位，得到的向量都一样。这一篇讲怎样把一个能读图的 LLM（VLM）训练成 **按指令输出向量** 的通用 embedding 模型：先讲表示怎么取、损失怎么写、batch 怎么凑大，再讲 MMEB 怎么评，最后给一个 2–3 周可做完的复现与消融计划。InfoNCE 的基础见 [对比学习](/notes/contrastive-learning/)，CLIP/SigLIP 的推导见 [为什么图像和视频能够进入语言模型](/notes/vision-video-algorithms/) 第 3–4 节，本篇不重复。

阅读入口：[多模态学习手册](/notes/multimodal-interview-guide/)。数值算例为教学构造；论文数字注明出处，可在原文核对。

## 1. 问题设定：embedding 模型的输入输出

**输入**：一个查询 $q$ 和一个候选 $c$，两者都可以是“指令 + 文本 + 图像”的任意组合。**输出**：两个 $d$ 维单位向量 $h_q,h_c$，相似度 $s(q,c)=h_q^\top h_c$。检索时候选库预先编码、建索引，查询来了只编码一次再做最近邻，这是 embedding 区别于 cross-encoder 的根本：**候选端的计算可以离线摊销**。代价是查询和候选在编码时互相看不见，所有交互都只能压进一次点积，这和 [搜索篇第 4–6 节](/notes/recsys-search/) 双塔、cross-encoder、ColBERT 的取舍完全一样。

四类任务都能写成“给查询，从候选里选对的那个”：

| 任务 | 查询 | 候选 | 例子 |
|---|---|---|---|
| 分类 | 指令 + 图 | 类别名文本 | “Represent the given image for classification” + 狗的照片 → `golden retriever` |
| VQA | 指令 + 图 + 问题 | 答案文本 | 图中有几个人 → `three` |
| 检索 | 指令 + 文/图/图文 | 图/文/图文 | 文搜图、图搜文、组合检索（图 + 修改说明 → 目标图） |
| 定位 | 指令 + 图 + 指代语 | 图中区域的裁剪图 | “left man in blue” → 对应裁剪 |

这正是 MMEB 的组织方式（VLM2Vec 论文 §2）：4 个元任务、36 个数据集，全部改写成排序题。

## 2. 为什么用 VLM 当编码器

CLIP 的文本塔是一个小 Transformer，论文里最大长度截断为 76 个 token（§2.4），读不懂长指令；图像塔和文本塔之间没有交叉注意力。VLM 本身就把图像 token 和文本 token 放在同一个序列里做因果注意力，天然支持图文混合输入，也能读懂“这是一个检索任务，请关注图中的文字”这类指令。缺点是它被训练来生成下一个 token，不是输出一个可比较的向量，所以要用对比学习重新训练。

VLM2Vec（Jiang et al., arXiv 2410.05160，ICLR 2025）的做法很直接：

1. 骨干用 Phi-3.5-V（4B 级），论文也给了 LLaVA-1.6 版本；
2. 查询前加任务指令，候选端也可以带指令；
3. 取**序列最后一个 token** 在最后一层的隐状态作为表示，再做 L2 归一化；
4. 用 InfoNCE（batch 内负例加上可选的难负例）在 MMEB 的 20 个训练集上对比训练（§3.1）。

**为什么取最后一个 token。** 因果注意力下只有最后一个位置能看到整个序列（指令、图像、文本），它是唯一“读完了全部输入”的位置。对比之下，mean pooling 会把大量只看到前缀的位置平均进去；CLS 取第一个 token 则在因果模型里什么都看不到。常见做法是在输入末尾显式加 EOS，取 EOS 位置；padding 必须左填充，或者按 `attention_mask` 找每行最后一个有效位置，否则会取到 pad 的隐状态。这是复现里最常见的 bug 之一。

**张量形状。** batch 有 $B$ 对 $(q_i,c_i)$。查询端前向后得到隐状态 $(B,L_q,D)$，按每行最后有效位置 gather 成 $(B,D)$，归一化得 $H_q$；候选端同理得 $H_c\in\mathbb R^{B\times D}$。Phi-3.5-V 的 $D=3072$。相似度矩阵 $S=H_qH_c^\top/\tau$ 的形状是 $(B,B)$，对角线是正样本。

## 3. 损失：InfoNCE、温度与梯度

单向 InfoNCE（VLM2Vec 只用查询到候选这一个方向）：

$$
\mathcal L=-\frac1B\sum_{i=1}^{B}\log\frac{\exp(s_{ii}/\tau)}{\exp(s_{ii}/\tau)+\sum_{j\ne i}\exp(s_{ij}/\tau)}.
$$

对 logit $z_{ij}=s_{ij}/\tau$ 求导，第 $i$ 行的梯度是 $\partial\mathcal L_i/\partial z_{ij}=p_{ij}-\mathbb 1[j=i]$，其中 $p_{ij}$ 是该行 softmax。所以对余弦相似度的梯度要再乘 $1/\tau$：正样本被往上拉，每个负样本按它当前的概率 $p_{ij}$ 被往下推。**分到概率多的负样本（难负例）挨推最多**，这就是对比学习自带的困难样本挖掘。

**手算：$B=3$**（教学构造）。三对查询和候选的余弦相似度：

$$
S=\begin{pmatrix}0.62&0.40&0.35\\0.30&0.55&0.50\\0.20&0.45&0.58\end{pmatrix}.
$$

取 $\tau=0.05$，第 2 行的 logit 是 $(6,11,10)$，softmax 为 $(0.0049,0.7275,0.2676)$。三行正样本概率分别是 0.9835、0.7275、0.9304，单行损失 $-\ln p$ 为 0.0166、0.3182、0.0721，平均 $\mathcal L=0.1356$。第 2 行对相似度的梯度：正样本 $(0.7275-1)/0.05=-5.45$，难负例 $c_3$ 为 $0.2676/0.05=5.35$，易负例 $c_1$ 只有 $0.0049/0.05=0.10$。几乎全部“推力”都给了 $c_3$。

同一个 $S$ 换温度：

| $\tau$ | 第 2 行正样本概率 | 平均损失 |
|---:|---:|---:|
| 0.02 | 0.9241 | 0.0268 |
| 0.05 | 0.7275 | 0.1356 |
| 0.10 | 0.5922 | 0.3154 |

温度越低，分布越尖，损失越集中在最难的那个负例上；温度越高，所有负例被均匀地推。VLM2Vec 用的是固定的 $\tau=0.02$（论文 §4 实验设置）。CLIP 让温度可学习，初始化为 0.07，并截断使 logit 的缩放不超过 100 倍（即 $\tau\ge0.01$，CLIP 论文 §2.5），原因是防止训练不稳定。低温度的风险是：一个**假负例**（其实也是对的候选）会拿到很大的梯度，把正确语义推开。

**双向还是单向。** CLIP 是对称损失（图到文、文到图取平均）。VLM2Vec 只用查询到候选的方向，因为查询和候选并不对称（查询带指令，候选可能只是类别名）。上面的矩阵如果按列再算一次文到图方向，平均损失是 0.1213，与行方向不同，说明两个方向的约束确实不同。

## 4. batch 为什么要大，GradCache 怎样凑

InfoNCE 的每个查询只能和 batch 里的 $B-1$ 个负例比。负例越多，softmax 分母越接近“和整个候选库比”，训练目标和检索时的真实场景越一致。VLM2Vec 的分析（论文 §4.3.2、Figure 4）显示 batch 从小到大，MMEB 分数逐步上升，主实验用 $B=1024$。但一个 4B 的 VLM，单卡一次只能放几个带图样本的前向和反向。

**为什么不能用梯度累积。** 梯度累积是把一个大 batch 切成小块，分别算 loss 再把梯度相加。对 CE 这种逐样本独立的损失，这与大 batch 完全等价。InfoNCE 不是：第 $i$ 个样本的损失依赖 batch 里所有候选的向量。切成 4 个样本一块，每个查询就只剩 3 个负例，目标函数已经变了。

**GradCache**（Gao et al., arXiv 2101.06983）把计算拆成两段：

1. **不建计算图地前向**全部 1024 个样本（分成每块 4 个），只存下最终的 embedding $H_q,H_c$，形状 $(1024,3072)$；
2. 在这 1024 个 embedding 上算完整的 InfoNCE，对 embedding 求梯度 $G=\partial\mathcal L/\partial H$，同样存下来；
3. **再逐块前向一次**（这次建图），用 $G$ 中对应的行作为上游梯度做反向（`h.backward(g)`），把参数梯度累加起来；
4. 全部块做完后，优化器更新一次。

由链式法则 $\partial\mathcal L/\partial\theta=\sum_i(\partial\mathcal L/\partial h_i)(\partial h_i/\partial\theta)$，第 3 步累加出的就是大 batch 的精确梯度。代价是每个样本多做一次前向，约多出三分之一的计算；显存上只需额外存 embedding 和它的梯度。手算：$1024\times2\times3072$ 个 fp32 数是 $25.2$ MB，相似度矩阵 $1024\times1024$ 是 4 MB，都可以忽略。VLM2Vec 在全参数训练时用子 batch 4、累积到 1024（论文 §3.2 与 §4 实验设置，8 张 H100）。

**两个细节。** ① 第 1 步和第 3 步的前向必须一致：dropout 要么关掉，要么保存并恢复随机数状态，否则第 3 步算出的 $h$ 和第 1 步不同，梯度就错了。② 多卡时要把所有卡的 embedding all-gather 到一起再算 loss，否则负例只来自本卡；gather 的张量本身没有梯度，要么用带梯度的 gather，要么只对本卡的行回传。

## 5. 负例：难负例、假负例与指令

**难负例。** batch 内的随机负例大多太容易（“狗”对“飞机”），梯度很快接近 0。常见做法是为每个查询额外配几个难负例：用一个已有的检索模型召回 top-$k$，去掉正例后取排名靠前的。LLaVE（arXiv 2503.04812）在损失里按难度给负例加权，让困难对贡献更多梯度。

**假负例。** 难负例挖得越狠，越容易挖到其实也正确的候选：同一个类别名出现在 batch 的两个分类样本里；“一个男人在骑车”的两张不同图片。处理方法有：同一 batch 里去掉与正例文本相同的候选；召回时跳过最前面的若干名（它们最可能是假负例）；用更强的 cross-encoder 过滤。分类任务尤其要按数据集分 batch 或对重复类名做掩码。

**指令。** VLM2Vec 的指令写成 “Represent the given image with the following question: …” 这样的模板，每个数据集一条。论文 §4.3.4 / Table 4 对比了有无任务指令：加指令让 VLM2Vec 提升 49.4%，却让 CLIP 下降 29.4%，因为 CLIP 的文本塔读不懂指令。直观原因是：同一张图，在“找相似商品”和“回答图里有几个人”两个任务下需要的表示不同，指令告诉模型该保留哪部分信息。

## 6. MMEB 怎么评

**组成**（VLM2Vec 论文 §2 与附录 A）：36 个数据集分 4 个元任务——分类 10 个、VQA 10 个、检索 12 个、定位 4 个；其中 20 个是分布内（可用来训练），16 个是分布外（只评测）。

**协议**：每个查询配一组候选（检索、VQA、定位都是 1 个正确加 999 个干扰，共 1000 个；分类是该数据集的全部类别名，例如 VOC2007 只有 20 个，候选数见 Table 1），模型给所有候选打分，看排第一的是否正确，指标是 **Precision@1**。随机猜在 1000 个候选里的期望是 0.1%。总分是 36 个数据集的简单平均，另外分别报告分布内（IND）和分布外（OOD）平均。

**主要结论**（论文 Table 2，arXiv v3）：

| 模型 | IND | OOD | 总分 |
|---|---:|---:|---:|
| CLIP（零样本） | 37.1 | 38.7 | 37.8 |
| E5-V（零样本） | 14.9 | 11.5 | 13.3 |
| CLIP 在 MMEB 上全参微调 | 47.6 | 42.8 | 45.4 |
| VLM2Vec，Phi-3.5-V，LoRA，bs 1024 | 66.5 | 52.0 | 60.1 |
| VLM2Vec，LLaVA-1.6，LoRA，1344×1344 | 67.5 | 57.1 | 62.9 |

看这张表要注意三点。一是 VLM2Vec 在 20 个 IND 数据集上训练过，IND 的提升里有一部分是“见过同分布数据”，衡量泛化要看 OOD 列；公平的对照是同样在 MMEB 上微调过的 CLIP（45.4），而不是零样本 CLIP。二是同一骨干下，分辨率从 336 提到 1344，LLaVA-1.6 版总分从 55.0 涨到 62.9，说明图像细节对 embedding 也很重要。三是论文指出 LLaVA-1.6 的预训练数据公开，几乎不与 OOD 集重叠，所以它的 OOD 分数不是靠见过测试数据得来的。

**后续工作。** VLM2Vec-V2（arXiv 2507.04590）提出 MMEB-V2，在 MMEB 上新增五类任务：视觉文档检索、视频检索、时间定位、视频分类和视频问答，模型也扩展到视频与文档输入。LLaVE 在损失里按难度给负例加权（第 5 节）。读这些论文时先看三件事：骨干是谁、训练数据是否包含 MMEB 的 IND 集、OOD 分数是多少。

## 7. 和推荐、RAG 的接口

多模态 embedding 在工业界最直接的用途是**召回**：商品图 + 标题编码成向量建 ANN 索引，用户的查询或行为序列编码后检索，这和 [推荐里的多模态 I2I](/notes/recsys-multimodal-i2i/) 是同一件事。另一个用途是**多模态 RAG** 的检索器：知识库里的截图、表格、图表直接编码，不必先 OCR。你 11 月的 Agent RL 项目里，可选的第 4 组消融就是把 10 月训出的 embedding 换进检索服务，看检索器质量怎样传导到策略的最终 EM，见 [Agent RAG](/notes/agent-rag/)。

上线时三个工程问题：**① 维度与存储**，3072 维 fp32 每个向量 12 KB，一亿条就是 1.2 TB，通常降到 512–1024 维（训练时加投影层或用 Matryoshka 式多粒度损失）并量化；**② 模型与索引成套更新**，换模型必须重编码全库，原因同 [召回第 9 节](/notes/wangshusen-recommender-retrieval/)；**③ 查询延迟**，4B 级的 VLM 编码一个带图查询比 CLIP 的双塔贵得多（参数量差一个数量级以上，图像还会被切成多个子图），上线前要实测延迟，必要时把查询端蒸馏到小模型。

抖音、快手、小红书等已经上线的多模态表征系统怎样构造训练数据、怎样接入下游、线上收益多大，见 [工业界多模态表征](/notes/multimodal-industrial-representation/)；按面试深挖顺序整理的问题见 [表征项目面试题库](/notes/multimodal-representation-interview/)。

## 8. 最小可行项目：2–3 周、单机 4 卡

目标是复现 VLM2Vec 的训练与 MMEB 评测闭环，跑出一张可以解释的结果表和 4 组消融。**不承诺具体分数**，每一步都和你看板 10 月的项目块对应。

| 阶段 | 做什么 | 验收 |
|---|---|---|
| 环境 | 拉官方 VLM2Vec 仓库，固定 commit；下载 MMEB 训练与评测集（先取 4–6 个数据集的子集） | 官方 checkpoint 在 2 个数据集上的 P@1 与论文相差在 1 个点以内 |
| CLIP 基线 | 用同一套评测脚本跑 CLIP ViT-L/14 零样本 | 有一张“数据集 × 模型”的表；随机候选的 P@1 约 0.1% 作为对照 |
| 单卡 / 4 卡 | 先单卡、LoRA、小 batch 跑通；再 4 卡 + GradCache 把 batch 提到 256–1024 | 单测：GradCache 梯度与小 batch 直接反传的梯度逐元素一致（相对误差 < 1e-3） |
| 首个结果表 | 在 IND 子集上训练，IND 与 OOD 子集上评测 | 表里同时有 CLIP、官方 checkpoint、自己训的模型 |
| 4 组消融 | ① batch 64 / 256 / 1024；② 有无指令；③ last-token 与 mean pooling；④ $\tau$=0.02 / 0.05 | 每个结论写成“因为……所以……”，附 3 个检索失败的例子 |
| 开源 | README 写清配置、显存、训练时间与复现命令 | 别人照 README 能在一台机器上复现那张表 |

**风险与验证。** ① 池化位置取错（右填充时取到 pad）：单测里构造长短不一的样本，断言取到的是每行最后一个非 pad 位置。② GradCache 前后两次前向不一致：关 dropout 或恢复随机数状态，用上面的梯度对比单测。③ 评测与训练的数据泄漏：OOD 集不得出现在训练集；同一个数据集的训练与测试切分不要混。④ 只看总分：IND 与 OOD 分开看，涨分只在 IND 时，要怀疑是拟合了训练分布。

## 9. 面试常问

**为什么不能用梯度累积代替大 batch？** InfoNCE 的每个样本损失依赖 batch 内所有候选，切块后负例变少，目标函数变了；GradCache 先无图前向拿全部 embedding、算出对 embedding 的梯度，再逐块重算前向并反传，得到的是大 batch 的精确梯度，代价是多一次前向。

**为什么取最后一个 token，不取 mean？** 因果注意力下只有最后一个位置看到了全部输入；mean 会混进大量只看到前缀的位置。要配合左填充或按 mask 定位。

**温度怎么影响训练？** 梯度是 $(p-y)/\tau$：温度低，分布尖，梯度集中在最难的负例上，对假负例更敏感；温度高，所有负例被均匀推，区分度下降。可学习温度要设上下界。

**IND 涨了 OOD 没涨说明什么？** 模型主要学到的是训练集的分布特征（类名、问题模板），而不是通用的图文对齐。要检查训练数据的多样性、指令是否过度贴合训练集模板，以及有没有泄漏。

**embedding 模型和 reranker 怎么配合？** embedding 负责从百万级候选里召回 top-100，reranker（cross-encoder 或 VLM 直接打分）对这 100 个精排。前者快、可离线编码，后者准但贵。

## 闭卷验收

不看资料写出 VLM2Vec 的四个设计选择（骨干、指令、池化、损失）；解释为什么因果模型要取最后一个 token、为什么要左填充；对给定的 $3\times3$ 相似度矩阵和温度手算行 softmax、单行损失与平均损失，并算出正样本、难负例、易负例各自对相似度的梯度；说清温度从 0.1 降到 0.02 时损失和梯度怎样变化；写出 GradCache 的四步、为什么得到精确梯度、多出多少计算；说出 MMEB 的元任务、数据集数、IND/OOD 划分和 Precision@1 协议；解释 VLM2Vec 与 CLIP 比较时哪一列更能说明泛化；最后讲出一个 4 卡、2–3 周的复现与 4 组消融计划，以及每一步的验收单测。

**参考。** [VLM2Vec / MMEB](https://arxiv.org/abs/2410.05160)（[代码](https://github.com/TIGER-AI-Lab/VLM2Vec)，[排行榜](https://huggingface.co/spaces/TIGER-Lab/MMEB)）；[CLIP](https://arxiv.org/abs/2103.00020)；[SigLIP](https://arxiv.org/abs/2303.15343)；[GradCache: Scaling Deep Contrastive Learning Batch Size under Memory Limited Setup](https://arxiv.org/abs/2101.06983)；[E5-V](https://arxiv.org/abs/2407.12580)；[VLM2Vec-V2 / MMEB-V2](https://arxiv.org/abs/2507.04590)；[LLaVE](https://arxiv.org/abs/2503.04812)；[Matryoshka Representation Learning](https://arxiv.org/abs/2205.13147)；[InfoNCE / CPC](https://arxiv.org/abs/1807.03748)。
