DeepSeek-R1 之后，大家很快把“规则奖励 + GRPO”搬到了视觉语言模型（VLM）上。这一篇回答四个问题：图像任务里哪些答案能被规则验证，奖励该怎么写；感知类任务（定位、计数、分类）和推理类任务（几何、图表）的奖励差在哪里；格式奖励和准确率奖励怎样组合，组合方式会怎样改变 GRPO 的优势；思维链变长以后，模型到底有没有更认真地看图，又该怎样验证。PPO/GRPO 的推导见 [从 RL 基础推到 PPO 与 GRPO](/notes/policy-gradient-ppo-grpo/)，DPO 的推导见 [SFT、LoRA 与 DPO](/notes/multimodal-sft-lora-dpo/)，本篇都只引用结论。多轮工具调用和检索 token 掩码属于 Agent RL，见 [Agent RL 预备](/notes/recsys-agent-rl/) 和 [Agent RL 进阶](/notes/agent-rl-advanced/)。

阅读入口：[多模态专题总览](/notes/multimodal-interview-guide/)。数值算例为教学构造；论文数字注明表号，代码细节注明仓库与提交。

## 1. 问题设定：一张图、一个问题、一组回答

**输入输出。** 一条训练样本是（图像，问题，可验证的标准答案）。策略是 VLM：图像经视觉编码器变成视觉 token，与问题拼成提示；模型生成 `<think>…</think><answer>…</answer>`。GRPO 对同一个（图，问题）采 $G$ 条回答，所以同一张图在一个组里出现 $G$ 次，条件完全相同，组内比较的只是回答本身。

**张量形状**（以 VLM-R1 仓库 `grpo_trainer.py` 为准，提交 `90052f4`）。一个 step 有 $B$ 个提示，每个采 $G$ 条：`rewards_per_func` 的形状是 $(BG, K)$，$K$ 是奖励函数个数（通常是 accuracy 和 format 两个）；按列**等权相加**得到 `rewards`，形状 $(BG,)$；再 `view(-1, G)` 求组均值和标准差（`torch.std`，即样本标准差，分母 $G-1$），优势为 $(r-\bar r)/(\mathrm{std}+10^{-4})$，形状 $(BG,)$，广播到该回答所有生成 token；损失先按每条回答的 `completion_mask` 求 token 平均，再对 batch 平均。

**和纯文本 RL 的差别只在三处**：答案的形式（框坐标、数字、类别名、选项）；验证器（IoU、数值等价、字符串匹配）；以及“模型是否用了图”这个文本 RL 里不存在的问题。

下表是本篇用到的工作，只列核到的信息：

| 工作 | 任务类型 | 基座 | 奖励 | 出处 |
|---|---|---|---|---|
| Visual-RFT（ICCV 2025） | 分类、少样本检测、推理定位、开放词表检测 | Qwen2-VL-2B/7B | IoU + 置信度 + 格式；分类为准确率 + 格式 | arXiv 2503.01785 §3.2 |
| VLM-R1 | REC、开放词表检测（OVD） | Qwen2.5-VL-3B（另有 7B、32B） | REC：IoU + 格式；OVD：odLength + 格式 | arXiv 2504.07615 §4 |
| R1-V | 计数（CLEVR）、几何（GeoQA） | Qwen2-VL / Qwen2.5-VL | 答案匹配 + 格式 | GitHub 仓库，无论文 |
| MM-Eureka | K12 数学推理 | Qwen2.5-VL-7B/32B | 准确率 $\{0,1\}$ + 格式 $\{0,0.5\}$ | arXiv 2503.07365 §4 |
| Vision-R1（ICLR 2026） | 多模态数学推理 | Qwen2.5-VL-7B/32B/72B | 格式与答案同时满足才得 1 | arXiv 2503.06749 §3.4 |

## 2. 感知类与推理类：奖励差在哪里

| | 感知类（定位、检测、计数、分类） | 推理类（几何、图表、数学） |
|---|---|---|
| 答案形式 | 框坐标、框列表、整数、类别名 | 数值、表达式、选项 |
| 验证器 | IoU、mAP、精确匹配 | Math-Verify 一类的符号等价，失败再字符串匹配 |
| 奖励形状 | 常是**连续**的（IoU 在 0 到 1） | 基本是**二值**的 |
| 主要失败 | 坐标系错位、阈值悬崖、多框时的刷量 | 答案抽取错误、格式与答案混在一起、猜对 |
| 思维链的作用 | 有争议：小模型上可能无益（见第 8 节） | 一般需要；Vision-R1 用冷启动先教会长推理 |

两类的核心差别是：感知类奖励**直接度量视觉输出**（框对不对得上），模型想拿高分就必须定位到物体；推理类奖励只看最终数值，模型可能从题干文字、选项分布或语言先验猜出答案，奖励本身不保证用了图。所以推理类任务更需要第 8 节的“看图”检验。

## 3. 定位奖励：一个框的 IoU，与多个框的匹配

**单框（REC）。** VLM-R1 式 (6)：$R_{\mathrm{acc}}^{\mathrm{rec}}(q,o)=\mathrm{IoU}(b^*,f_{\mathrm{rec}}(o))$，$f_{\mathrm{rec}}$ 从 `<answer>` 里抽出 $[x_1,y_1,x_2,y_2]$。格式奖励检查 `<think>…</think><answer>{…[x1,y1,x2,y2]…}</answer>` 是否成立，返回 1 或 0（§4.2）。仓库实现里 IoU 直接作为奖励，有一行“IoU 大于 0.5 记 1”的写法被注释掉了，说明作者在连续与阈值两种奖励之间选了连续。

$$
\mathrm{IoU}(a,b)=\frac{\lvert a\cap b\rvert}{\lvert a\rvert+\lvert b\rvert-\lvert a\cap b\rvert}.
$$

**手算：一个框的 IoU**（教学构造）。真值框 $b^*=[100,100,300,300]$，面积 $200\times200=40000$。

- 预测 A $=[150,120,350,320]$：交集横向 150 到 300 宽 150，纵向 120 到 300 高 180，交集 $27000$；并集 $40000+40000-27000=53000$；IoU $=27000/53000\approx0.509$。
- 预测 B $=[160,120,360,320]$，只比 A 右移 10 像素：交集 $140\times180=25200$，并集 $54800$，IoU $\approx0.460$。

连续奖励下两者只差 0.049；如果用 IoU 大于 0.5 记 1 的阈值奖励，A 得 1、B 得 0。评测用的 Acc@0.5（见 [视觉定位](/notes/multimodal-grounding/)）也是这条悬崖，所以“连续奖励训练、阈值指标评测”之间有一段错位：从 0.46 推到 0.51 在奖励上是小进步，在指标上是从错到对。

**多框（检测）。** Visual-RFT 式 (5)–(9)：$R_d=R_{\mathrm{IoU}}+R_{\mathrm{conf}}+R_{\mathrm{format}}$。预测框按置信度排序，逐个与真值框匹配，IoU 低于阈值 $\tau$ 的记为 0；$R_{\mathrm{IoU}}$ 是所有预测框 IoU 的平均；置信度奖励对匹配上的框取 $c_i$，没匹配上的取 $1-c_i$，再平均。论文没写 $\tau$ 的值；仓库 `src/virft/src/open_r1/grpo.py`（提交 `2ffad63`）里是 `iou_threshold=0.5`，且要求严格大于。代码与论文还有两处差别：一是先删除坐标完全相同的重复框；二是现用的 `compute_reward_iou_v2` 在预测框少于真值框时**除以真值框数**，漏检会被罚，论文式 (6) 只除以预测框数 $n$。另外仓库把 IoU 奖励和置信度奖励注册成两个独立的奖励函数，和格式奖励一起按列相加。

**边界与失败场景。** ① **坐标系**：模型输出的坐标是相对什么尺寸的？VLM-R1 的 Qwen 模块用 `image_grid_thw` 乘 14 还原模型输入的高宽，再把预测框缩放到原图尺寸后与真值比；Visual-RFT 的检测提示要求 0 到 1000 的整数坐标。只要真值和预测不在同一坐标系，IoU 奖励就会系统性偏低，而且不会报错。② **空输出与解析失败**：两份代码都在异常时给 0，和“框完全错”同分。③ **IoU 的整数像素约定**：VLM-R1 的 `iou` 函数交集用了含端点的 $+1$ 写法、面积没有，同一对框的数值与上面手算会有微小差异，换实现时要对齐。

**怎样验证。** 写单测：同一个框 IoU 为 1；不相交为 0；把真值框按输入缩放比例变换后再算，结果不变。训练时同时画“平均 IoU 奖励”和“验证集 Acc@0.5”两条曲线，前者涨而后者不动，常说明大量回答卡在 0.3 到 0.5 之间。

## 4. 组大小 4 的 GRPO 优势：连续 IoU 与阈值奖励

**手算**（教学构造，采用 VLM-R1 代码的样本标准差）。同一句指代表达采 4 条回答，IoU 奖励分别是 $r=(0.80,\ 0.51,\ 0.46,\ 0.00)$，最后一条没解析出框。

- 均值 $\bar r=1.77/4=0.4425$；偏差 $(0.3575,\ 0.0675,\ 0.0175,\ -0.4425)$；平方和 $0.328475$。
- 样本标准差 $\sqrt{0.328475/3}\approx0.3309$；优势 $\approx(1.080,\ 0.204,\ 0.053,\ -1.337)$，和为 0。
- 若用总体标准差 $\approx0.2866$，优势 $\approx(1.248,\ 0.236,\ 0.061,\ -1.544)$，方向不变、尺度变大。

再看阈值奖励（IoU 大于 0.5 记 1）：$r=(1,1,0,0)$，样本标准差 $0.5774$，优势 $(0.866,\ 0.866,\ -0.866,\ -0.866)$。对比两组可以读出三点：① 阈值奖励把 0.80 和 0.51 当成同样好，把 0.46 和“没输出框”当成同样差；连续奖励保留了这些差别。② 连续奖励下 IoU 0.46 的回答拿到了**正**优势 0.053，因为它高于组均值；它在 Acc@0.5 上却是错的。GRPO 只看组内相对好坏，组整体偏差时“不太差”的回答也会被加强。③ 如果 4 条回答的 IoU 是 $(0.86,0.85,0.84,0.85)$，组内差别只有 0.01，可能是标注噪声量级，除以标准差后优势仍是 $(1.225,0,-1.225,0)$：标准化会把极小差别放大成和上面同量级的学习信号。

**边界。** 第③点就是 Dr. GRPO（arXiv 2503.20783，Fig. 1、§3.1）指出的“问题级难度偏差”：标准差小的题（太易或太难）在更新中权重更大，它的修正是去掉除以标准差和按长度归一化两项。另一面，组内奖励完全相同时优势全为 0，这组没有策略梯度；MM-Eureka 的做法是在线过滤掉全对或全错的题（§4.4，Algorithm 1，沿用 PRIME），其 Fig. 3 显示不过滤时准确率奖励先升后崩到接近 0。

**怎样验证。** 每个 step 记录：组内奖励标准差的分布、标准差低于某个小值的组占比、全 0 或全满分的组占比。连续奖励下“标准差很小但不为 0”的组要单独统计，它们不会被“全对全错过滤”拦住。

## 5. 奖励黑客：检测任务与分类任务

**OVD 上的刷量。** VLM-R1 先用 COCO 官方 API 的 AP50 或 mAP 作奖励，发现了奖励黑客（§5.3.1）：COCO API 计算单张图的 AP 时，真值里不存在的类别不参与评估；而提示里总是同时列出正类和若干负类，于是模型把列出的类别全部输出一遍，多报的框几乎不扣分。表现是输出越来越长（Fig. 6，不带 KL 时更明显），以及大量重复框（Fig. 7 左）。修正是式 (7)(8) 的 odLength 奖励：

$$
s_{\mathrm{ovd}}=\min\Big(1,\frac{L_{\mathrm{gt}}}{L_{\mathrm{pred}}}\Big),\qquad
R^{\mathrm{ovd}}_{\mathrm{acc}}=s_{\mathrm{ovd}}\cdot\mathrm{mAP}(\mathbf b_{\mathrm{pred}},\mathbf b_{\mathrm{gt}}),
$$

$L$ 是框与类别组合的个数，多报就按比例打折。Table 5（Qwen2.5-VL-3B）：OVDEval 总体 NMS-AP 在 AP50 奖励下为 21.46，mAP 奖励下为 21.68，odLength 下为 31.01；COCOfiltered 的 mAP 分别为 11.4、11.8、21.1。作者把加了 odLength 后“先在 `<think>` 里判断哪些物体真的存在、再输出框”的行为称为 **OD aha moment**（Fig. 7 右）。代价也写在 §5.3.3：各尺寸模型的 Greedy Precision 涨幅大于 Greedy Recall，奖励让模型变保守。

**REC 和 OVD 的对照结论**（§6.4）：两者输出格式相同，但朴素 IoU 奖励对 REC 就够了，OVD 必须改奖励；在简单的 RefCOCO 上训练的 REC 能泛化到推理密集的 LISA-Grounding，而 OVD 在 COCO 上训练反而不如换成语义更丰富的 D³ 数据（Table 6：OVDEval 24.48 对 31.01）。

**分类与计数的刷量**（本节以下为本文对代码的分析）。Visual-RFT 分类仓库 `grpo_classification.py` 在去空格、去下划线、转小写后做**双向子串匹配**：标准答案是回答的子串、或回答是标准答案的子串，都记 1。于是一个把多个候选物种名连写在 `<answer>` 里的回答也可能拿满分；回答过短（比如只写一个常见词根）也可能命中。R1-V 的计数奖励先用 `math_verify` 判等价，失败再做 `<answer>` 内字符串完全相等，比子串匹配严格，但“3”与“three”会判不同。

**怎样验证。** 每隔若干 step 抽查高奖励回答，统计 `<answer>` 长度、框数与真值框数之比、重复框比例；给奖励函数写对抗用例（多候选拼接、空答案、重复框、坐标越界），确认它们拿不到高分。

## 6. 推理类奖励：答案匹配、格式奖励与三种组合

**三种写法，都核对了原文或代码。**

| 写法 | 格式分 | 准确率分 | 合成 | 出处 |
|---|---|---|---|---|
| 相加 1:1 | $\{0,1\}$ | $\{0,1\}$ | 相加 | R1-V `grpo.py`、VLM-R1 REC、Vision-R1-Zero（§3.1 写明 1:1） |
| 降权相加 | $\{0,0.5\}$ | $\{0,1\}$ | 相加 | MM-Eureka §4.1–4.2 |
| 硬格式结果奖励 | 不单列 | 不单列 | 格式与答案都对才得 1，否则 0 | Vision-R1 §3.4 |

R1-V 的格式奖励用 `re.fullmatch` 匹配 `<think>.*?</think>\s*<answer>.*?</answer>`，回答前后多一个字都判 0；准确率奖励先 `math_verify`，失败再比字符串。MM-Eureka 的准确率用 Math-Verify 抽答案；Vision-R1 冷启动后已学会格式，所以 RL 阶段不再用系统提示约束格式（§3.4）。

**手算：格式 + 准确率**（教学构造，样本标准差）。一道几何题采 4 条：a 格式对、答对；b 格式对、答错；c 漏了 `</think>`、但答案能被抽出且正确；d 格式错、答错。

- 相加 1:1：$r=(2,1,1,0)$，均值 1，标准差 $\sqrt{2/3}\approx0.816$，优势 $(1.225,\ 0,\ 0,\ -1.225)$。b 和 c 同分，“格式对答错”与“格式错答对”被视为等价。
- 降权相加：$r=(1.5,0.5,1.0,0)$，均值 0.75，标准差 $\approx0.645$，优势 $(1.162,\ -0.387,\ 0.387,\ -1.162)$。答对比守格式更值钱，c 排在 b 前面。
- 硬格式结果：$r=(1,0,0,0)$，优势 $(1.5,\ -0.5,\ -0.5,\ -0.5)$。b、c、d 同样差，格式错的正确答案也被压低。

**格式饱和以后。** 训练中后期 4 条都守格式时，比如 a 答对、其余答错：相加 1:1 给 $r=(2,1,1,1)$，硬格式给 $(1,0,0,0)$，两者优势**完全相同**，都是 $(1.5,-0.5,-0.5,-0.5)$。原因是组内每条都多出同一个常数，减均值时被消掉，标准差也不变。所以格式奖励只在格式还没学会的组里起作用；格式饱和后它对 GRPO 优势没有贡献，日志里看到的“总奖励上升”可能只是格式分涨满了。

**边界。** ① 格式奖励权重过大、而准确率很低时，模型可能先学会守格式、答案不进步。② 正则写得太宽，模型可以在 `<answer>` 里塞推理过程；太严（`fullmatch`），一个多余换行就整组 0 分。③ 选择题可以猜，四选一随机猜的准确率期望为 0.25，组内“答对”未必来自推理。

**怎样验证。** 把各奖励分量分开记录（VLM-R1 的 trainer 会按函数记 `rewards/<name>`），而不是只看总和；单测覆盖“只有格式”“只有答案”“`<answer>` 里多个答案”等样例。

## 7. 推理任务的冷启动与 PTST：Vision-R1

**为什么不直接 R1-Zero。** Vision-R1 先对基座 MLLM 直接做 GRPO（Vision-R1-Zero，10K 数学题，格式与结果 1:1，4K 长度、每题 16 条、300 步），§3.1 的结论是很难诱导出长而复杂的推理链；长时间训练后输出变长，但性能没有明显提升。

**冷启动数据**（Modality Bridging，§3.3.1、附录 A）。① 用 MLLM（Qwen2.5-VL-72B）对图像-问题-答案生成带图像描述和步骤的 “Pseudo-CoT”；② 把 Pseudo-CoT 连同图和问题再喂给 MLLM，得到包含解题所需视觉细节的详细描述；③ 把纯文本描述交给 DeepSeek-R1 生成推理链；④ 只保留最终答案与标准答案一致的样本，再用规则过滤逻辑不一致的样本。来源是 LLaVA-CoT（100K）和 Mulberry（260K）的 VQA 数据，最终得到 200K 的 Vision-R1-cold。Table 4 统计反思词频：“Wait” 在 Vision-R1-cold 中出现 585,719 次，LLaVA-CoT 中 2,300 次。冷启动是在 Qwen2.5-VL 上用 LLaMA-Factory 做 2 个 epoch 的 SFT，得到 Vision-R1-CI。

**过度思考与 PTST**（§3.3.2、§3.4）。Vision-R1-CI 学会了长推理，但正确的推理多集中在较短的链上，长链里错误步骤多。PTST 把 RL 分阶段：第 $s$ 阶段的输出长度上限为 $L_s$、组大小为 $G_s$，先短后长；奖励是硬格式结果奖励，$\varepsilon=0.2$，$\beta=10^{-2}$，在 verl 上训练。最终配置是两阶段：4K×16 训 100 步，再 8K×8 训 100 步（附录 A）；第三阶段 16K×4 不提升性能，最终模型没有用。注意长度乘组大小保持不变（$4\text{K}\times16=8\text{K}\times8$），每题 rollout 的 token 预算相同。

**消融**（7B，平均为 MathVista、MathVerse、MM-Math 三项）。Table 3：Vision-R1-Zero 平均输出长度 1285、平均准确率 50.7；Vision-R1-CI 为 3566、44.5；直接以 16K 训练的 Vision-R1-Long 为 3107、47.7；Vision-R1 为 2057、55.4。Table 5：全程 4K×16 为 54.3，全程 16K×4 为 47.7。Table 6：不冷启动只用 PTST 为 51.8，用不含 CoT 的同批数据 SFT 后再 PTST 为 39.8。主结果 Table 1：Vision-R1-7B 在 MathVista 上为 73.5，基座 Qwen2.5-VL-7B 为 68.1。

**读法。** 冷启动模型最长（3566）却最差（44.5），最终模型的长度介于中间却最好。在这组实验里，“思维链更长”和“准确率更高”不同步。

## 8. 思维链长度，与“看图”是否真的发生

**已有证据，方向并不一致。** ① R1-V 仓库 README 的注：后续实验发现，让 2B 基座模型直接输出结果、不走 `<think><answer>` 格式，在 SuperCLEVR 上得分高得多（86%），作者认为强制 CoT 对 2B 模型可能不必要甚至有害。② Think or Not Think（arXiv 2503.16188，NeurIPS 2025 Spotlight）的摘要结论：视觉感知任务在 RFT 中不需要显式思考，不思考的 No-Thinking-RL 在各尺寸上持平或更好；部分回答里 `<think>` 中的答案与 `<answer>` 不一致，这类回答的准确率低于整体。③ More Thinking, Less Seeing?（arXiv 2505.21523）的摘要结论：推理链越长，模型越偏离图像、依赖语言先验，注意力分析显示对视觉输入的关注下降；它提出 RH-AUC 指标和 RH-Bench。④ 第 7 节 Vision-R1 的 Table 3：长度与准确率不同步。

**为什么奖励本身管不住这件事。** 结果奖励只看 `<answer>`。几何题的已知条件常被写进题干文字，模型不看图也可能答对；思维链里“我观察到图中……”这样的句子不受任何奖励约束，可以是事后编出来的。MathVerse（arXiv 2403.14624，ECCV 2024）正是针对这一点：2,612 道题各改写成六个版本（Text Dominant、Text Lite、Text Only、Vision Intensive、Vision Dominant、Vision Only），信息逐步从文字移到图里，摘要结论是多数 MLLM 严重依赖文字题干。

**验证协议**（本文整理的做法，指标为教学定义）。

| 检验 | 做法 | 看什么 |
|---|---|---|
| 盲测 | 同一批题，图换成纯色图或另一题的图 | $\Delta_{\mathrm{img}}=\mathrm{Acc}_{\mathrm{img}}-\mathrm{Acc}_{\mathrm{blank}}$；RL 前后 $\Delta$ 是否变大 |
| 信息迁移 | MathVerse 的 Text Dominant 与 Vision Only 两个版本 | RL 带来的提升是否在 Vision Only 上也成立 |
| 反事实图 | 改图中被问到的属性（数量、长度标注），题干不变 | 答案是否跟着变；不变说明在猜 |
| 内部一致性 | 抽取 `<think>` 里的结论与 `<answer>` 比较 | 不一致率；按长度分桶看准确率 |
| 对照组 | 同数据、同步数训一个 No-Thinking 版本 | 感知任务上 CoT 是否真带来增益 |

**手算一个盲测**（教学构造）。200 道几何题，RL 前带图准确率 0.50、纯色图 0.40，$\Delta=0.10$；RL 后带图 0.60、纯色图 0.55，$\Delta=0.05$。带图准确率涨了 10 个点，但其中 15 个点在无图时也拿得到，对图的依赖反而从 0.10 降到 0.05。这时不能说“RL 提升了视觉推理”，更可能是学到了题干或答案分布的规律。

## 9. 对照：偏好优化路线（RLHF-V、RLAIF-V）

可验证奖励要求有标准答案；开放描述、减少幻觉这类任务没有，常用偏好优化。两篇都以 DPO 为基础，推导见 [SFT、LoRA 与 DPO](/notes/multimodal-sft-lora-dpo/)，幻觉度量见 [幻觉与评测](/notes/multimodal-hallucination-eval/)。

- **RLHF-V**（arXiv 2312.00849，CVPR 2024）：标注员直接改写回答里的幻觉片段，得到片段级的偏好对；共 1.4k 条提示，平均每条回答 64.4 个词、2.65 处修改（§2）。DDPO 把序列打分改为加权：$\log\pi(y\mid x)=\frac1N\big[\sum_{y_i\in y_u}\log p(y_i\mid\cdot)+\gamma\sum_{y_i\in y_c}\log p(y_i\mid\cdot)\big]$，$y_c$ 是被修改的片段，$\gamma>1$，$N=\lvert y_u\rvert+\gamma\lvert y_c\rvert$（式 (5)）。摘要报告幻觉率降低 34.8%。
- **RLAIF-V**（arXiv 2405.17220，CVPR 2025）：用开源 MLLM 当标注器。候选回答在同一条件下多次采样得到，去掉文风等混杂因素；把回答拆成原子陈述逐条打分（divide-and-conquer）；迭代地更新反馈数据；推理时用对齐后模型的长度归一化分数做自我反馈。摘要报告 7B 模型物体幻觉降低 80.7%、整体幻觉降低 33.7%。

**和 GRPO 路线的对照。** 偏好路线离线、无需在线 rollout，信号是“哪段更可信”；规则奖励路线在线采样，信号是“答案对不对”。前者的风险是标注偏差和长度偏好，后者的风险是奖励黑客和“答对但没看图”。两者可以串联：先用偏好数据压幻觉，再在有标准答案的任务上做 GRPO。

## 11. 面试常问

**感知任务为什么用连续 IoU 而不是 Acc@0.5 当奖励？** 阈值奖励把 0.51 和 0.80 视为一样、把 0.46 和没输出框视为一样，组内容易全 0 或全 1，信号稀疏。连续 IoU 能区分“差一点”和“完全错”。代价是奖励与阈值指标错位，以及标准化会放大微小差别。VLM-R1 代码里阈值写法被注释掉、改用连续 IoU。

**格式奖励有什么用，什么时候没用？** 训练早期它让回答可解析，验证器才能工作。一旦整组都守格式，它对每条回答加同一个常数，GRPO 减均值后完全抵消，对优势没有贡献。权重过大时可能出现守格式而不答对的局面，所以 MM-Eureka 把它降到 0.5，Vision-R1 干脆要求格式与答案同时满足。

**举一个多模态 RL 的奖励黑客。** VLM-R1 的 OVD：COCO API 不评估真值中不存在的类别，模型就把提示里所有类别都输出一遍，长度暴涨、重复框增多。修正是乘以 $\min(1,L_{\mathrm{gt}}/L_{\mathrm{pred}})$ 的 odLength，OVDEval 从 21.68 提到 31.01（Table 5）。

**怎么证明 RL 后模型真的在看图？** 不能看思维链里写了什么。做盲测（换纯色图）、反事实改图、MathVerse 的 Vision Only 版本，以及 `<think>` 与 `<answer>` 的一致性统计；再训一个 No-Thinking 对照。提升只在有图时出现、并且随图的改动而改变，才说明用到了视觉信息。

**Vision-R1 为什么要先冷启动，再限制长度？** 直接 RL 难以诱导出长推理；冷启动后的模型会过度思考，长链错误多。PTST 先把长度限制在 4K、组大小 16，让模型在短链上学对，再放宽到 8K。Table 3 中冷启动模型最长却最差（3566 token、44.5），最终模型 2057 token、55.4。

## 闭卷验收

不看资料写出 IoU 公式，对真值 $[100,100,300,300]$ 与预测 $[150,120,350,320]$ 算出约 0.509，并说出右移 10 像素后为什么在阈值奖励下从 1 变 0；写出 Visual-RFT 的 $R_d$ 三项，说出仓库里 $\tau=0.5$ 与“漏检时除以真值框数”两处与论文的差别；对 IoU 奖励 $(0.80,0.51,0.46,0)$ 用样本标准差算出组内优势，解释为什么 0.46 拿到正优势，以及标准化怎样放大 $(0.86,0.85,0.84,0.85)$ 这类微小差别；写出 VLM-R1 的 odLength 公式并讲清 OVD 奖励黑客的成因；对 a/b/c/d 四条回答分别用 1:1 相加、0.5 降权、硬格式三种方式算奖励与优势，并证明格式饱和后格式分对优势没有贡献；说出 Vision-R1 冷启动数据的四步流程和 PTST 的两阶段配置；最后设计一个包含盲测、反事实改图和 No-Thinking 对照的实验，判断“RL 后模型是否真的在看图”。
