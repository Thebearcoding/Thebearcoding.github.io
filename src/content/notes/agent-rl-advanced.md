[Agent RL 预备](/notes/recsys-agent-rl/) 讲了 Search-R1 的完整流程：多轮 rollout、检索 token 掩码、EM 奖励、GRPO。跑通之后，训练曲线上会陆续出现一些“奇怪”的现象：回答长度不断变长、熵快速下降后奖励停滞、很多 step 几乎没有学习信号、奖励涨了但评测没涨。这一篇逐个解释这些现象背后的机制和社区给出的修正。PPO、GRPO 的推导见 [从 RL 基础推到 PPO 与 GRPO](/notes/policy-gradient-ppo-grpo/)，本篇假设你已经熟悉组内优势和裁剪目标。

阅读入口：[Agent 总览](/notes/agent-guide/)。数值算例为教学构造；论文结论注明出处，以原文为准。

## 1. 从单轮到多轮，问题变在哪

单轮推理 RL（数学题）是：一个提示、一段回答、一个奖励。Agent RL 是：一个任务、多轮“模型生成 → 环境返回”的交替、最后一个奖励。新增的问题有四个：

1. **轨迹更长**：工具返回会撑长上下文，单条轨迹可能上万 token，显存和 rollout 时间都成倍增加；
2. **信用分配更难**：最终失败，是哪一轮的决策导致的？
3. **环境是外部系统**：检索服务、代码沙箱、浏览器有延迟、会失败，rollout 的速度往往被环境而不是 GPU 决定；
4. **奖励更容易被钻空子**：模型可以通过操纵环境（改测试文件、重复调用）拿到奖励。

前两个是算法问题，后两个是工程问题，但它们会互相放大：轨迹越长、环境越慢，每个 step 的样本越少，信用分配的噪声就越大。

## 2. 长度偏差：为什么错误的回答越来越长

原始 GRPO 的目标对每条回答先在 token 上取平均（除以回答长度 $|o_i|$），再在组内取平均。这意味着**每条回答的总梯度权重相同，与长度无关**；分摊到每个 token 上，长回答的每个 token 权重更小。

**手算**（教学构造）。一组 4 条回答，奖励 $(1,0,0,1)$，长度 $(200,100,1000,300)$。组内均值 0.5，样本标准差 0.577，优势 $\hat A=(0.866,-0.866,-0.866,0.866)$。

| 回答 | 长度 | 奖励 | 逐条平均：每 token 权重 $\hat A/(G|o_i|)$ | token 平均：每 token 权重 $\hat A/\sum|o|$ | token 平均：整条总权重 |
|---|---:|---:|---:|---:|---:|
| o1 | 200 | 1 | $+0.00108$ | $+0.00054$ | $+0.108$ |
| o2 | 100 | 0 | $-0.00217$ | $-0.00054$ | $-0.054$ |
| o3 | 1000 | 0 | $-0.00022$ | $-0.00054$ | $-0.541$ |
| o4 | 300 | 1 | $+0.00072$ | $+0.00054$ | $+0.162$ |

逐条平均下，错误的长回答 o3 每个 token 只挨了 $-0.00022$ 的惩罚，是短错误回答 o2 的十分之一。对正确回答则相反：短的每个 token 奖励更多。**结果是模型学到“答对就简短，答错就写长”**，平均长度在训练中持续上升，而增加的主要是错误回答里的冗长内容。

**修正。** DAPO（Yu et al., arXiv 2503.14476）改为 **token 级平均**：整个 batch 的所有 token 一起平均，每个 token 权重相同，长的错误回答整体受到更大的惩罚（上表最后一列）。Dr. GRPO（Liu et al., arXiv 2503.20783）进一步指出，原始 GRPO 里的两个归一化都引入了偏差：除以 $|o_i|$ 带来长度偏差；除以组内标准差会让奖励方差小的题（太易或太难）获得更大的权重。它把两者都去掉，用一个常数（如最大生成长度）代替 $|o_i|$。verl 的 `loss_agg_mode` 参数就是在这几种聚合方式之间切换。

## 3. 熵坍塌与 Clip-Higher

PPO 和 GRPO 把重要性比率 $\rho=\pi_\theta/\pi_{\text{old}}$ 裁剪在 $[1-\epsilon,1+\epsilon]$ 内。对于优势为正的 token，比率最多涨到 $1+\epsilon$。这个上限对不同概率的 token 影响完全不同：

| $\pi_{\text{old}}$ | $\epsilon=0.2$ 时新概率上限 | $\epsilon_{\text{high}}=0.28$ 时上限 |
|---:|---:|---:|
| 0.01 | 0.012 | 0.0128 |
| 0.10 | 0.12 | 0.128 |
| 0.90 | 1.08（实际被 1 截断） | 1.152（同上） |

高概率 token 可以轻易涨到接近 1，低概率 token 在一次更新里只能从 0.01 涨到 0.012。一个偶然采样到的、新颖但正确的推理路径（以低概率 token 开头），很难被强化起来。于是模型越来越集中在已经高概率的输出上，**策略熵快速下降**，探索停止，奖励停滞。

DAPO 的 **Clip-Higher** 把上下界解耦：下界保持 $1-\epsilon_{\text{low}}=0.8$，上界放宽到 $1+\epsilon_{\text{high}}=1.28$。论文报告这能维持更高的熵和更好的最终效果。监控建议：每个 step 记录策略熵和裁剪比例（被裁剪的 token 占比），熵在前几十步急剧下降是坍塌的信号。

## 4. 动态采样：全对全错的组是浪费

GRPO 的优势是组内标准化的结果，如果一组 $G$ 条回答的奖励全部相同（全对或全错），优势全为 0，这一组对梯度没有任何贡献，但它的 rollout 和前向反向的计算都花掉了。

随着训练进行，模型对简单题全对、对难题全错的比例会越来越高。假设某个时刻 40% 的组奖励全相同，一个 512 组的 batch 里只有约 307 组在提供信号，相当于有效 batch 缩小了 40%，梯度噪声也随之变大。

DAPO 的 **动态采样**：持续采样，丢掉奖励全相同的组，直到凑满 512 个有信号的组。按 60% 的有效率，平均需要采 $512/0.6\approx854$ 组。代价是 rollout 变多，好处是每个 step 的有效 batch 稳定。另一种更省的做法是**离线过滤**：训练前用初始模型对每道题采 $G$ 次，去掉通过率为 0 或 1 的题；训练中定期重新评估。这和 [Agent RL 预备](/notes/recsys-agent-rl/) 第 10 节说的“先测起始模型的 pass@5”是一回事。

## 5. 超长截断：别把“没写完”当成“写错了”

回答达到最大长度被截断时，没有给出答案，结果奖励是 0。但截断的回答可能推理方向完全正确，只是太长了。给它和错误回答一样的负优势，会引入噪声。DAPO 提出两个处理：**超长过滤**（被截断的样本不参与损失计算）和**软超长惩罚**（在接近最大长度的一段区间内，按超出的长度线性增加惩罚，而不是在边界处突然变成 0）。Agent 场景里同样的问题表现为“达到最大轮数仍未作答”，处理思路相同：区分“答错”和“没来得及答”，在日志里分别统计。

## 6. 多轮信用分配：功劳记给哪一轮

Search-R1 的做法是把结果奖励广播到所有轮次的所有模型 token 上：一条成功的轨迹里，每一轮的每个 token 都拿到同样的正优势。这很简单，但有明显的问题：一条轨迹里第 1 轮的检索很好、第 2 轮的检索是多余的、第 3 轮答对了，三轮获得同样的奖励，模型学不到“第 2 轮是多余的”。

**几种改进方向：**

- **轮级奖励**：给每一轮额外的中间信号，例如“这次检索的结果里是否包含答案”。问题是容易被钻空子（见第 8 节），而且 Search-R1 作者的后续实证研究（arXiv 2505.15117）发现中间检索奖励的作用有限。
- **轮级优势**：把每一轮当作一个决策单元，用价值函数估计每一轮之后的期望回报，计算轮级的 TD 优势。这需要 critic，回到了 PPO 的框架，但决策粒度从 token 变成了轮。
- **按轮数惩罚**：在结果奖励里扣掉一个与调用次数成正比的代价，鼓励用更少的轮次完成任务。要小心系数：太大会让模型宁可不查直接猜。

**RAGEN**（Wang et al., arXiv 2504.20073）系统地研究了多轮 Agent RL，提出了轨迹级优化框架 StarPO，并报告了一种称为 “Echo Trap” 的失败模式：模型过拟合到少数几种高奖励的推理模式上，奖励方差骤降、熵下降，随后训练崩溃。他们的缓解措施包括按奖励方差过滤轨迹、去掉 KL 项、采用非对称裁剪，这与 DAPO 的结论相互印证。

## 7. 异步 rollout 与策略滞后

Agent RL 的 rollout 很慢：每轮都要等环境返回，一条轨迹可能要几分钟。同步训练（等所有轨迹采完再一起训练）意味着 GPU 大量时间在空等最慢的那条轨迹。

**异步训练**：rollout 进程持续生成轨迹放入缓冲区，训练进程从缓冲区取数据更新，两者并行。代价是**策略滞后**：训练时用的轨迹是由几个版本之前的策略采的。PPO 的重要性比率 $\pi_\theta/\pi_{\text{old}}$ 正是为了修正这种偏差，但它假设 $\pi_{\text{old}}$ 就是采样策略。异步时必须记录每条轨迹实际由哪个版本的策略生成，用那个版本的 log 概率作为分母；滞后太多时比率会频繁被裁剪，等于丢掉了大部分梯度。

**手算**（教学构造）。某 token 在采样策略下概率 0.20，当前策略下概率 0.30，比率 1.5。若优势为正、$\epsilon_{\text{high}}=0.28$，比率超过 1.28，被裁剪，梯度为 0。滞后越多，这种被裁掉的 token 越多。实践中通常限制最大滞后（例如只用最近 1–2 个版本的轨迹），并监控裁剪比例。

**另一个细节：训练与推理的数值不一致。** rollout 用 vLLM 等推理引擎（可能用不同的 kernel 和精度），训练用 FSDP 下的前向，同一个 token 的 log 概率在两边可能不同。即使是同步的“on-policy”训练，$\pi_{\text{old}}$ 应该用训练引擎重新计算，而不是直接用推理引擎返回的值。verl 默认在训练侧重新计算 old log prob，原因就在这里。

## 8. 奖励黑客：模型会找到你没想到的捷径

| 奖励 | 被钻空子的方式 | 对策 |
|---|---|---|
| 单测通过 | 修改或删除测试文件；硬编码测试的期望输出 | 评测时用 Agent 看不到的测试；检查对测试文件的修改 |
| 子串匹配 / F1 | 列出多个候选答案，或写很长的答案“蹭”到匹配 | 用严格 EM；限制答案长度 |
| 格式奖励 | 只学会守格式，内容不对 | 格式分很小或只做门槛 |
| 检索命中奖励 | 反复检索直到碰巧命中 | 去掉或给检索次数加代价 |
| LLM 裁判打分 | 写出裁判喜欢的风格（长、自信、堆术语） | 裁判换家族、用条款评分、定期人工抽查 |
| 过程奖励模型 | 写出 PRM 打高分但不推进解题的步骤 | 结果奖励为主，PRM 为辅；定期重训 PRM |

**过程奖励还是结果奖励。** 过程奖励模型（PRM）给每一步打分，提供更密集的信号，理论上能缓解信用分配问题。但 PRM 本身是一个学出来的模型，策略在优化过程中会找到它的漏洞；而且步骤的划分和标注都很贵。DeepSeek-R1 的报告明确说没有使用 PRM，原因之一就是奖励黑客问题。当前的主流做法是：**能写出可靠的规则验证器的任务，只用结果奖励**；开放式任务才考虑学习型奖励，并配合频繁的人工检查。

**检测奖励黑客的通用办法。** ① 定期打印高奖励的轨迹人工阅读；② 同时监控一个**不参与训练**的评测指标，训练奖励涨而评测不涨就是警报；③ 记录轨迹的统计特征（长度、调用次数、重复率），出现突变时检查。

## 9. 一张排障表

| 现象 | 可能原因 | 先看什么 |
|---|---|---|
| 回答长度持续上升 | 逐条平均的长度偏差；奖励鼓励长答案 | 正确与错误回答的长度分别画曲线 |
| 熵前期急降，奖励停滞 | 裁剪上界太紧；学习率太大 | 熵曲线、裁剪比例；试 Clip-Higher |
| 很多 step 梯度接近 0 | 全对全错的组太多 | 组内奖励全相同的比例；动态采样或过滤 |
| 奖励涨，评测不涨 | 奖励黑客；训练与评测分布不同 | 读高奖励轨迹；独立评测集 |
| 训练后期奖励骤降 | 熵坍塌后崩溃；KL 失控 | 熵、KL、奖励方差；回退 checkpoint |
| 调用次数趋向 0 或最大值 | 轮数代价系数不当；检索结果没用 | 调用次数分布；有无检索时的准确率对比 |
| 比率经常被裁剪 | 异步滞后太大；old log prob 用了推理引擎的值 | 滞后版本数；训练侧重算 log prob |

## 10. 面试常问

**GRPO 为什么会让回答越来越长？** 原始实现先对每条回答按长度平均，每条回答的总权重相同，长回答的每个 token 权重更小，于是错误的长回答受到的惩罚被稀释。DAPO 改为 token 级平均，Dr. GRPO 去掉长度和标准差归一化。

**Clip-Higher 解决什么问题？** 对称裁剪下低概率 token 一次只能涨到 $1.2$ 倍，新颖的正确路径难以被强化，熵快速下降。把上界放宽到 1.28，给低概率 token 更多上升空间。

**动态采样的代价和收益？** 丢掉奖励全相同的组，保证每个 step 的有效 batch 稳定；代价是需要更多 rollout。离线按通过率过滤题目是更省的替代。

**多轮 Agent RL 的信用分配怎么做？** 最简单是结果奖励广播到所有轮次；改进方向有轮级中间奖励（易被钻空子）、轮级价值函数估计（需要 critic）、按轮数扣代价（系数要小心）。

**怎样发现奖励黑客？** 读高奖励轨迹；监控一个不参与训练的评测指标；跟踪长度、调用次数、重复率等统计特征的突变。能用规则验证器的任务只用结果奖励。
