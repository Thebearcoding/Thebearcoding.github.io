生成式推荐要让模型“写出”下一个物品。物品 ID 有上千万个，直接当词表太大，也没有任何结构：编号 1 和编号 2 的物品毫无关系。文本标题又太长，而且不唯一。**语义 ID**（Semantic ID，SID）的做法是把每个物品的内容向量量化成几个离散码，例如 $(12,201,7)$。这样上千万个物品只需要几百到几千个 token，相似物品共享前缀，新物品只要有内容就能分到 ID。

这一篇是你 GRID 项目的理论部分。阅读入口：[全覆盖教程](/notes/recsys-llm4rec-guide/)。数值算例为教学构造。

## 1. 从连续向量到离散码：VQ-VAE

VQ-VAE 有一个编码器 $E$、一个码本 $\{e_1,\dots,e_K\}$ 和一个解码器 $D$。输入 $x$ 编码为 $z=E(x)$，取最近的码字 $e_k$，$k=\arg\min_j\|z-e_j\|$，再解码重建。损失有三项：

$$
\mathcal{L}=\underbrace{\|x-D(e_k)\|^2}_{\text{reconstruction}}
+\underbrace{\|\mathrm{sg}[z]-e_k\|^2}_{\text{codebook}}
+\beta\,\underbrace{\|z-\mathrm{sg}[e_k]\|^2}_{\text{commitment}}.
$$

$\mathrm{sg}$ 是停止梯度。码本项只更新码字，把它拉向编码器输出；承诺项只更新编码器，防止编码器输出四处漂移、总也不靠近任何码字。$\beta$ 常取 0.25。

**argmin 不可导，梯度怎么回到编码器？** 用直通估计（STE）：

$$
z_q=z+\mathrm{sg}[e_k-z].
$$

前向时 $z_q=e_k$，解码器看到的是量化结果；反向时 $\mathrm{sg}$ 内的部分没有梯度，$\partial z_q/\partial z=I$，重建损失的梯度原样穿过量化步骤传给编码器。代价是这个梯度是近似的：它假装量化不存在。

## 2. 残差量化：一层不够，就量化剩下的

单层码本要表示一千万个物品，$K$ 得很大，而且大码本更容易坍塌（第 6 节）。**残差量化**（RQ）用 $L$ 层小码本逐层逼近：

$$
r_0=z,\qquad c_d=\arg\min_j\|r_{d-1}-e^{(d)}_j\|,\qquad r_d=r_{d-1}-e^{(d)}_{c_d},\qquad d=1,\dots,L.
$$

物品的 SID 就是 $(c_1,\dots,c_L)$，重建为各层码字之和。第一层捕捉粗粒度（大类），后面逐层细化，天然是“从粗到细”的层级结构，正好适合逐 token 生成：先写大类，再写小类。容量是 $K^L$，$K=256$、$L=3$ 时约 1677 万。

**手算。** 物品向量 $z=(0.9,0.2)$。第一层码本 $\{(1,0),(0,1)\}$：到第一个的平方距离 $0.01+0.04=0.05$，到第二个 $0.81+0.64=1.45$，选 $c_1=0$，残差 $r_1=(-0.1,0.2)$。第二层码本 $\{(0,0.2),(-0.1,0),(0.1,-0.1)\}$：平方距离分别为 0.01、0.04、0.13，选 $c_2=0$，残差 $r_2=(-0.1,0)$。SID 是 $(0,0)$，重建 $(1,0.2)$，平方误差 0.01。

**RQ-VAE** 把编码器、$L$ 层码本、解码器一起训练，每层都有码本项和承诺项：

$$
\mathcal{L}_{\mathrm{RQ}}=\|x-\hat x\|^2+\sum_{d=1}^{L}\Big(\|\mathrm{sg}[r_{d-1}]-e^{(d)}_{c_d}\|^2+\beta\|r_{d-1}-\mathrm{sg}[e^{(d)}_{c_d}]\|^2\Big).
$$

## 3. 不训练网络：RQ-KMeans

**RQ-KMeans**（也叫 Res-KMeans、残差 K-means）不要编码器和解码器：第一层对所有物品向量做 K-means，得到 $c_1$ 和残差；第二层对残差做 K-means；依此类推。它简单、稳定、不会因为训练不当而坍塌，GRID 默认就提供它。

普通 K-means 的簇大小可能极不均匀，几个大簇装下大半物品，前缀区分度很差。**平衡 K-means** 限制每个簇大小相同（约 $|V|/K$），快手 OneRec 采用了这种做法。代价是相似物品可能被强行分到不同簇。

## 4. 不分层：PQ 与 OPQ

**乘积量化**（PQ）把 $D$ 维向量切成 $M$ 段，每段用自己的码本独立量化，SID 是 $M$ 个码。**OPQ** 先学一个正交旋转 $R$，让切段后的量化误差最小：

$$
\min_{R,\{C_m\}}\ \sum_i\|x_i-\mathrm{quantize}(Rx_i)\|^2,\qquad R^\top R=I.
$$

PQ 的各段地位平等，没有“第一个码是大类”的层级。对向量检索这没关系，对逐 token 生成却是缺点：生成第一个码时，模型没有一个有意义的粗粒度目标。快手 OneSearch 的 RQ-OPQ 把两者结合：前几层用残差量化保留层级，最后对残差做 OPQ 增加区分度。

## 5. 不要码本：FSQ 与哈希

**FSQ**（有限标量量化）把编码器输出的每一维压到有界区间，再四舍五入到 $L_i$ 个整数之一：

$$
\hat z_i=\mathrm{round}\big((L_i-1)\,\sigma(z_i)\big),\qquad \sigma\in(0,1).
$$

码本是隐式的网格，大小 $\prod_i L_i$，没有码本损失，也就不存在“有些码字永远没人用”的坍塌；取整同样用 STE 传梯度。

**SimHash** 也能当 SID：$h$ 个随机超平面给出 $h$ 位二值码，每 8 位拼成一个 0–255 的 token。TIGER 论文的消融比较过随机 ID、基于 LSH 的语义 ID 和 RQ-VAE 语义 ID。监督或深度哈希学出来的二值码也属于这一类，比随机超平面保留更多语义。它和 RQ 的关键差别在层级：各位平等，第一个 token 不对应大类。这正是你项目里“二值哈希分组 tokenizer”要回答的问题：**输了多少，输在层级还是输在信息量。**

| 方法 | 是否要训练 | 层级 | 坍塌风险 | 适合 |
|---|---|---|---|---|
| RQ-VAE | 编码器 + 码本 | 有 | 高，需要技巧 | 追求效果、愿意调参 |
| RQ-KMeans | 只做聚类 | 有 | 低 | 基线、大规模 |
| PQ / OPQ | 聚类 + 旋转 | 无 | 低 | 检索、作特征 |
| RQ-OPQ | 两者组合 | 前几层有 | 低 | 既要层级又要区分度 |
| FSQ | 编码器 | 无 | 无 | 训练稳定性优先 |
| 哈希 | 无或学习 | 无 | 无 | 极简基线、你的对照组 |

## 6. 码本坍塌

**现象**：一层有 256 个码字，训练后只有十几个被用到；或者绝大多数物品挤进少数码字。后果是 SID 区分度差、冲突多，生成模型的第一个 token 几乎没有信息。

**度量**（你的 `diagnostics.py` 要算的）：

- 利用率：被至少一个物品用到的码字数 $/K$。
- 熵与困惑度：码字使用分布 $p_k$ 的熵 $H=-\sum_k p_k\log p_k$，上限 $\log K$；困惑度 $e^{H}$ 可理解为“等效用了几个码字”。
- 基尼系数：衡量分布不均，0 为完全均匀。

**成因**：码字初始化离数据太远，从未被选中，也就从未被更新；编码器输出集中在一小块区域。有研究还观察到残差量化的中间层码字分布特别集中，像一个沙漏。

**对策**：用第一批数据做 K-means 初始化码本；把长期没被用到的码字重置为随机的编码器输出；用 EMA 更新码本；把向量先 L2 归一化或降维；平衡分配（平衡 K-means，或用 Sinkhorn 类方法约束分配均匀）。LETTER 等工作还在 tokenizer 训练中加入协同信号与多样性正则。

## 7. 冲突与去重

$K^L$ 的容量远大于物品数，冲突仍然常见，因为物品不是均匀分布的：同一款手机的不同颜色，内容向量几乎一样。**冲突率** $=1-$ 唯一 SID 数 $/$ 物品数。

常见做法是在末尾追加一位去重码：冲突的物品依次编号 0、1、2……。GRID 的 README 特别提醒，追加去重位之后，下游模型的层数参数要比 tokenizer 的层数多 1。去重位没有语义，只是让 ID 唯一；冲突越多，模型越要靠这一位“死记”，所以冲突率本身就是要报告的指标。

## 8. 下游：TIGER 怎样用 SID 推荐

TIGER（*Recommender Systems with Generative Retrieval*，NeurIPS 2023）的流程：

1. 用文本编码器（论文用 Sentence-T5）把物品的标题、类目、品牌等编码成向量，再用 RQ-VAE 得到 SID。
2. 把用户历史物品的 SID 依次展开成 token 序列，用编码器-解码器 Transformer，训练解码器逐 token 生成下一个物品的 SID，损失是交叉熵。
3. 推理时 beam search 生成 $B$ 个 SID，映射回物品。

**约束解码。** 模型可能生成一个不存在的 SID 组合。把所有合法 SID 建成前缀树，每一步只允许走树上存在的分支，非法 token 的概率置零后重新归一化。beam 大小决定召回数量与成本：解码 $L$ 步、每步保留 $B$ 条，成本约正比于 $L\times B$。

**为什么有用**：词表只有 $L\times K$ 量级，参数可以花在 Transformer 上；相似物品共享前缀，长尾物品可以从同类热门物品“借”统计强度；新物品有内容就有 SID，论文也讨论了冷启动与用温度采样增加多样性。

**边界**：生成式召回一次只产生 $B$ 个候选，$B$ 增大时成本线性上升；SID 由内容决定，内容相似但用户行为差异大的物品会被混在一起，这是 [LLM4Rec](/notes/recsys-llm4rec-paradigms/) 里“行为对齐”工作要解决的。

## 9. tokenizer 指标与下游效果不总是一致

重建误差更小的 tokenizer 不一定带来更好的推荐。SID 要同时满足两件事：**含有足够的语义信息**（重建好、近邻保持好），以及**容易被生成模型学会**（前缀有意义、分布不过度偏斜）。码本越大、层数越多，信息越多，但每个 token 的预测越难。

Snap 的 GRID（*Generative Recommendation with Semantic IDs: A Practitioner's Handbook*，CIKM 2025）把 tokenizer、编码器、解码器做成可替换模块，系统消融后发现，许多常被忽视的架构细节会显著影响结果。所以你的实验要**固定下游，只换 tokenizer**，并且同时报告 tokenizer 指标和下游指标，才能说清楚因果。

## 10. 不生成，只当特征

语义 ID 不一定用来生成。另一条更容易落地的路线是把 SID 当成排序模型的**稀疏特征**，替换或补充随机哈希的 item ID：

- Google 的 *Better Generalization with Semantic IDs* 在 YouTube 排序模型里用 SID 的前缀（n-gram）或 SentencePiece 式切分生成 embedding，长尾和新物品能共享头部物品学到的参数，同时不明显损害头部效果。
- 快手 QARM 先用行为数据对齐多模态向量，再量化成可训练的码，供下游模型当 ID 特征使用，详见 [多模态推荐](/notes/recsys-multimodal-i2i/)。
- 淘宝、Meta 等也有工作用 SID 提升冷启动或 embedding 的稳定性（物品 ID 频繁新增、删除时，SID 前缀相对稳定）。

这条路线不需要改召回架构，面试时可以作为“生成式推荐成本太高时的折中方案”来讲。
