[Agent RL 预备](/notes/recsys-agent-rl/) 已经讲了 Search-R1 的四对标签、检索 token 掩码、EM 奖励、GRPO 组内优势和 verl 配置。那一篇的设定是“只在终点给一个 0/1，再把同一个优势广播到所有生成 token”。轮次一多、工具一复杂，这个设定就会暴露三个问题：**哪一轮该为成败负责**（信用分配）、**除了最终答对还该奖励什么**（奖励设计），以及**为什么训练到一半会塌**（稳定性）。本篇依次回答这三个问题，最后讲 DAPO 的四项改动和 rollout 工程。PPO、GAE、GRPO 的推导见 [从 RL 基础推到 PPO 与 GRPO](/notes/policy-gradient-ppo-grpo/)，这里不重复。

阅读入口：[Agent 专题总览](/notes/agent-guide/)。数值算例均为教学构造，数字已手算验证；论文数字注明出处章节或表号。

## 1. 从单轮到多轮：轨迹长什么样

单轮 RL（数学题）里，一条样本是“提示 + 一段回答”。多轮 Agent 的一条轨迹是交替序列：

$$
\tau=(x,\ a_1,\ o_1,\ a_2,\ o_2,\ \dots,\ a_K),
$$

$a_k$ 是第 $k$ 轮模型生成的 token 段（思考 + 工具调用或答案），$o_k$ 是环境返回的观测（检索结果、代码输出、网页）。张量层面仍是 `responses` 形状 $(Nn, L_r)$ 加一个 `loss_mask`，观测段为 0（见 [预备篇第 3 节](/notes/recsys-agent-rl/)）。多出来的是一个**轮边界**：知道第 $k$ 轮从哪个 token 开始、到哪个 token 结束，才能做轮级奖励和轮级优势。实现上通常再存一个 $(Nn, L_r)$ 的 `turn_id` 张量，观测段记 $-1$。

RAGEN 把这种设定写成 StarPO（State-Thinking-Actions-Reward Policy Optimization）：优化目标是整条轨迹的期望回报 $J(\theta)=\mathbb E_\tau[R(\tau)]$，其中 $\tau$ 是包含推理的多轮交互全序列（[RAGEN §2.2，式 (2)](https://arxiv.org/abs/2504.20073)）。它既可以接 PPO（token 级优势），也可以接 GRPO（轨迹级归一化奖励广播到所有 token）。

## 2. 信用分配：轨迹级、轮级、token 级

**输入输出。** 输入：每条轨迹的奖励（终点一个数，或每轮一个数）、轮边界、可选的价值估计。输出：$(Nn, L_r)$ 的 `advantages`，只在 `loss_mask=1` 处有意义。

三种分法：

| 粒度 | 优势怎么来 | 需要什么 | 代表 |
|---|---|---|---|
| 轨迹级 | 组内标准化终点奖励，广播到全部生成 token | 只需结果奖励 | Search-R1 的 GRPO、StarPO+GRPO |
| 轮级 | 每轮一个优势，广播到该轮 token | 轮级奖励，或轮边界处的价值 / 同状态分组 | GiGPO 的 step 级优势 |
| token 级 | 逐 token 的价值做 GAE | critic | PPO（Search-R1 默认、ReTool） |

**手算：一条 3 轮轨迹**（教学构造）。问题是两跳 QA。第 1 轮查到桥接实体（20 个生成 token），第 2 轮几乎重复了上一次查询（10 个 token），第 3 轮作答且答对（6 个 token），共 36 个生成 token。

*方案 A：轨迹级。* 同组 4 条轨迹的终点奖励为 $(1,0,0,0)$，用样本标准差，这条轨迹的优势是 1.5（算法同预备篇第 4 节）。36 个 token 全部拿到 +1.5。按轨迹内 token 平均，第 1、2、3 轮的权重分别是 $20/36\approx0.556$、$10/36\approx0.278$、$6/36\approx0.167$。也就是说，那次浪费的重复查询拿到了 28% 的正向推力。

*方案 B：轮级。* 设计轮级奖励：查询命中含答案的段落 $+0.2$，重复查询 $-0.1$，终点答对 $+1$，即 $r=(0.2,-0.1,1)$。取 $\gamma=1$，各轮的 reward-to-go 为

$$
G_1=0.2-0.1+1=1.1,\quad G_2=-0.1+1=0.9,\quad G_3=1.
$$

假设一个轮级 critic 在每轮开始时估计 $V(s_1)=0.5$、$V(s_2)=1.0$、$V(s_3)=0.8$（第 1 轮查到桥接实体后，状态看起来很有希望）。$\lambda=1$ 时 $A_k=G_k-V(s_k)=(0.6,\,-0.1,\,0.2)$；$\lambda=0$ 时用一步 TD：$\delta_1=0.2+1.0-0.5=0.7$，$\delta_2=-0.1+0.8-1.0=-0.3$，$\delta_3=1+0-0.8=0.2$。两种取法下第 2 轮都拿到**负**优势，重复查询被压低。这正是轮级分配要的效果，代价是要么设计轮级奖励，要么训练一个价值模型。

*方案 C：token 级。* PPO 的 critic 对每个 token 前缀给价值，奖励放在每轮最后一个 token 上。$\gamma=\lambda=1$ 时 $A_t=G_t-V(s_t)$。若第 3 轮写 `<answer>` 前价值为 0.8、写到答案最后一个 token 前升到 0.95，则该轮第一个 token 的优势是 0.2，最后一个是 0.05：信用集中到“价值跳变”的 token 上。是否靠谱完全取决于 critic 是否学得动长轨迹，观测段又不参与损失，critic 跨过一大段文档仍要给出连贯的价值。

**不用 critic 的轮级办法：GiGPO。** GiGPO 保留轨迹级的组相对优势 $A^E$，再把不同轨迹里**完全相同的环境状态**当锚点，把从同一锚点出发的动作分成一组，用折扣回报 $R_t=\sum_{k\ge t}\gamma^{k-t}r_k$（$\gamma=0.95$）算 step 级相对优势 $A^S$，最后 $A=A^E+\omega A^S$，$\omega=1$（[GiGPO 方法节](https://arxiv.org/abs/2505.10978)）。某状态只出现一次时 step 组大小为 1，没有可比对象，退化成 GRPO。论文 Table 1：Qwen2.5-1.5B-Instruct 上 ALFWorld 成功率 GRPO 72.8% → GiGPO 86.1%，WebShop 成功率 56.8% → 67.4%。边界：锚点要求状态精确相等，ALFWorld、WebShop 这类离散文本环境容易命中；开放域搜索的观测几乎不会逐字相同，锚点组会大量退化。另有工作系统比较了终点、延迟、逐轮三种奖励结构下的 GRPO/PPO 变体，摘要结论是逐轮稠密奖励更好、PPO 更稳（[Wei et al., arXiv 2505.11821](https://arxiv.org/abs/2505.11821)）。

**边界与失败。** ① 轮级奖励是人写的启发式，“命中段落 +0.2”会诱导模型多搜、只搜好命中的东西。② 轮级 critic 在轮数少、样本少时估不准，$\lambda=0$ 的偏差会直接写进优势。③ token 平均与轨迹平均会让长轮次天然占更多权重（见第 6 节）。

**怎样验证。** 离线：在固定验证集上看平均轮数、重复查询率、无效调用率随训练的变化，而不只看最终准确率。消融：同一奖励下比较 A/B/C 三种分配，记录收敛步数和最终 EM。抽查：挑优势为负的中间轮，人工判断它是否确实是坏动作。

## 3. 奖励设计：结果、格式、工具调用

**结果奖励**：EM、单测通过、任务成功，稀疏但难以投机。Search-R1 只用 EM、不加格式分；ReTool 只用 $\pm1$ 的答案正确性，明确不给“代码可执行”加分，理由是避免奖励投机（[ReTool 方法节](https://arxiv.org/abs/2504.11536)）。

**格式奖励或惩罚**：RAGEN 对没写出合法 `<think>…<answer>` 结构的输出扣 0.1（[RAGEN §3.2、附录 C.2](https://arxiv.org/abs/2504.20073)）。格式分的目的是让解析器能解析，权重过大就会出现“只守格式不答对”的局部最优。

**工具调用奖励：ToolRL 的分解。** ToolRL（Qian et al., arXiv 2504.13958）在每一步都有标准工具调用的数据上训练，把多步对话拆成单步样本（前文作为上下文），每步对照标准调用打分（[ToolRL 方法节](https://arxiv.org/abs/2504.13958)）：

- 格式：$\mathcal R_{\text{format}}\in\{0,1\}$，要求的特殊标记齐全且顺序正确记 1。
- 工具名：$r_{\text{name}}=\lvert N_G\cap N_P\rvert/\lvert N_G\cup N_P\rvert$（Jaccard）。
- 参数名：对每个标准调用，参数键集合的 Jaccard 求和，范围 $[0,\lvert G\rvert]$。
- 参数值：逐个参数精确匹配计数，范围 $[0,\sum_j\lvert\text{keys}(G_j)\rvert]$。
- 预测与标准调用之间取使总分最大的匹配，总分记 $R_{\max}$；满分 $S_{\max}=1+\lvert G\rvert+\sum_j\lvert\text{keys}(G_j)\rvert$。

$$
\mathcal R_{\text{correct}}=6\cdot\frac{R_{\max}}{S_{\max}}-3\in[-3,3],\qquad
\mathcal R=\mathcal R_{\text{format}}+\mathcal R_{\text{correct}}\in[-3,4].
$$

**手算：带格式分的奖励组合**（教学构造）。标准调用 `get_weather(city="Beijing", unit="C")`，$S_{\max}=1+1+2=4$。同组 4 条输出：

| 输出 | 格式 | name | param | value | $R_{\max}$ | $\mathcal R_{\text{correct}}$ | 总分 |
|---|---:|---:|---:|---:|---:|---:|---:|
| ① `get_weather(city="Beijing", unit="F")` | 1 | 1 | 1 | 1 | 3 | 1.5 | 2.5 |
| ② `get_weather(city="Beijing", unit="C")` | 1 | 1 | 1 | 2 | 4 | 3 | 4 |
| ③ `search_web(query="Beijing weather")` | 1 | 0 | 0 | 0 | 0 | $-3$ | $-2$ |
| ④ 标签缺失，解析失败，按无调用处理 | 0 | 0 | 0 | 0 | 0 | $-3$ | $-3$ |

（④“解析失败按无调用处理”是本文的约定，论文没有逐条说明。）均值 0.375，样本标准差 $\approx3.400$，组内优势 $\approx(0.625,\ 1.066,\ -0.698,\ -0.993)$。两点观察：参数值错一个（①）仍拿到明显正优势，这就是细粒度奖励提供的“部分对”信号；③ 和 ④ 只差 1 分格式分，说明在这个量纲下格式只是次要项。ToolRL 的消融也指向这一点：格式与正确性等量纲（都在 $[-1,1]$）不如放大正确性（$[-3,3]$）；细粒度分解优于整调用精确匹配；加长度奖励鼓励长推理并不稳定提升，小模型上还会变差（[ToolRL 分析节](https://arxiv.org/abs/2504.13958)）。训练用 GRPO、去掉 KL、每题采 4 条；摘要报告相对基座提升 17%、相对 SFT 提升 15%。

**边界。** ① 这种奖励需要每一步的标准调用，本质上是“带参考答案的过程奖励”，换到开放环境（网页、代码库）就没有参考调用。② 同一意图可以有多种合法调用（换个等价工具、参数顺序或单位），精确匹配会误罚。③ 拆成单步样本后，策略看到的前文是标准轨迹而不是自己的轨迹，这在训练上更接近“单步决策 + 教师强制前文”，不是真正的在策略多轮 RL。

**验证。** 对奖励函数写单测（格式错、缺参数、多余调用、等价调用）；训练中分项记录 format / name / param / value 四条曲线，只涨 format 不涨 value 就是在投机。

## 4. 过程奖励：PRM 与 ORM

ORM（outcome reward model）对整条解答给一个分；PRM（process reward model）对每一步给“这步对不对”的概率。Let's Verify Step by Step（Lightman et al., arXiv 2305.20050）的做法：人工给每一步标正 / 负 / 中性，得到 PRM800K（12K 道 MATH 题、75K 条解答、80 万个步骤标签）；PRM 对整条解答的打分是**各步正确概率之积**。在 MATH 测试集的 500 题子集上做 best-of-1860 重排，PRM 选出的解答正确率 78.2%，ORM 72.4%，多数投票 69.6%。注意它只做重排，**没有用 PRM 做 RL**（论文原话说不尝试用 RL 改进生成器）。

**手算**（教学构造）。解答甲三步的正确概率 $(0.9,0.8,0.95)$，乘积 $0.684$；解答乙 $(0.99,0.99,0.5)$，乘积 $0.490$。乘积会惩罚“某一步明显可疑”的解答，即使其余步骤都很稳；步数越多，乘积天然越小，长解答吃亏，比较时要注意长度。

**放到 Agent 训练里。** DeepSeek-R1 在“不成功的尝试”中列了 PRM 的三个问题：通用推理里很难定义细粒度的“步”；判断中间步对错本身就难；一旦引入模型化的 PRM，就会出现奖励投机，重训奖励模型又增加成本和流程复杂度（[DeepSeek-R1 §4.2](https://arxiv.org/abs/2501.12948)）。Agent 场景里“步”反而好定义（一轮就是一步），所以常见做法是规则化的过程信号：工具调用是否合法、查询是否重复、代码是否报错，或像 ToolRL 那样对照参考调用。用学习出来的 PRM 给 Agent 每轮打分，在本文核实的范围内没有足够证据支持它稳定有效，面试时应讲清这是开放问题。逐步奖励如何变成 token 优势，见 [PPO/GRPO 笔记 9.4 节](/notes/policy-gradient-ppo-grpo/)。

**验证。** 先离线评估 PRM：在带步骤标签的保留集上算逐步 AUC，再做 best-of-N 重排看最终准确率，过关后才接进 RL；RL 中定期用人工或强模型复核高 PRM 分的轨迹。

## 5. 多轮 RL 为什么会塌：RAGEN 的 Echo Trap

RAGEN 在 Bi-Arm Bandit、Sokoban、FrozenLake 和 WebShop 上用 StarPO 训练（符号任务用 Qwen2.5-0.5B-Instruct，WebShop 用 3B）。它观察到一种反复出现的塌缩，称为 **Echo Trap**：训练早期智能体给出多样的符号推理，训练后塌缩成确定性的、重复的模板（§4.1）。例如 Bandit 任务中第 0 步还在比较各种假设，第 150 步几乎每条都写成同一句“我最初的打算是选 Dragon 臂”（Table 6）。

**早期信号。** 论文的结论是：奖励标准差和熵往往在性能下降**之前**就出现波动，梯度范数尖峰通常标志着不可逆的塌缩（§4.1）。所以监控面板上至少要有组内奖励标准差、生成熵、梯度范数三条曲线，而不是只看平均奖励。

**StarPO-S 的三项改动**（§4.2）：

1. 按不确定性过滤：对每个初始状态，用多次 rollout 的回报标准差 $U(s_0)=\mathrm{Std}_{\tau\sim\pi_\theta(\cdot\mid s_0)}[R(\tau)]$ 衡量不确定性，只保留 $U$ 最高的前 $p\%$，默认 $p=25$；
2. 加 critic，用 PPO 式的价值基线代替纯组内归一化；
3. 去掉 KL 项、使用非对称裁剪（$\epsilon_{\text{low}}=0.2,\ \epsilon_{\text{high}}=0.28$，附录 D），即 DAPO 的 Clip-Higher。

论文报告这些改动推迟或消除了塌缩。其他结论：初始状态更多样（每题采样数更少，例如 4 条）泛化更好；每轮允许 5–6 个动作最好；rollout 越新鲜（Online-1，每批都重新采样）收敛越快（§4.3）。关于推理：只奖励最终结果时，多轮环境里的推理链会随训练持续变短，甚至出现与动作对不上的“幻觉推理”；作者认为需要细粒度、能感知推理的奖励（§4.4）。

**边界。** 这些结论来自小模型和玩具环境；“保留 25%”这个比例在真实工具任务上未必合适。按方差过滤和 DAPO 的动态采样是同一思路的强弱两版：DAPO 只扔掉方差为 0 的组，StarPO-S 只留方差最大的四分之一。

## 6. DAPO 的四项改动，放到 Agent 训练里

DAPO（Decoupled Clip and Dynamic sAmpling Policy Optimization，arXiv 2503.14476）在 Qwen2.5-32B 上训练数学推理，奖励为 $\pm1$（§2.4 式 (7)），去掉了 KL，组大小 16，AIME 2024 得 50 分，超过 DeepSeek-R1-Zero-Qwen-32B 的 47 分，且只用了一半训练步数。Table 1 的逐项累加：朴素 GRPO 30 → 超长过滤 36 → Clip-Higher 38 → 软超长惩罚 41 → token 级损失 42 → 动态采样 50。

**① Clip-Higher**（§3.1）。上下界解耦，$\epsilon_{\text{low}}=0.2$、$\epsilon_{\text{high}}=0.28$。论文的例子：$\epsilon=0.2$ 时，概率 0.01 的 token 一步最多涨到 0.012，概率 0.9 的 token 上界是 1.08（实际不受限）。按同样算法，$\epsilon_{\text{high}}=0.28$ 时前者可以涨到 0.0128。对 Agent 的意义：“换一个工具”“换种查法”这类探索性动作的首个 token 往往概率很低，对称裁剪会把它们压住，熵就塌了，和 RAGEN 的 Echo Trap 是同一类现象。

**② 动态采样**（§3.2）。只保留 $0<\lvert\{o_i:\ o_i\text{ correct}\}\rvert<G$ 的题，过采样直到 batch 填满。**手算**（教学构造）：8 道题、每题 $G=4$，答对条数为 $(4,0,2,1,4,0,3,0)$。全对或全错的 5 道组内优势为 0，被过滤，剩 3 道题、12 条轨迹，有效比例 $12/32=37.5\%$。要凑满 8 道有效题，按这个比例期望要采约 $8/0.375\approx21.3$ 道题，即约 3 个生成批次。若每道题的单条成功率为 $p$ 且独立，一组是“混合组”的概率是 $1-p^G-(1-p)^G$：$G=4$ 时 $p=0.5$ 为 0.875，$p=0.9$ 或 $0.1$ 都只有约 0.344。Agent 任务的特点是一次 rollout 很贵（多轮、要调工具），过采样意味着成倍的工具调用费用，所以更常见的做法是训练前先测每题 pass@G、筛掉太易和太难的题，动态采样只作兜底。论文认为过采样不一定拖慢训练，因为同步生成的耗时主要被长尾样本占据（§3.2）。

**③ token 级损失**（§3.3）。GRPO 的原写法是先在每条样本内对 token 取平均、再对样本取平均；DAPO 改成全组 token 一起平均，$\frac{1}{\sum_i\lvert o_i\rvert}\sum_i\sum_t(\cdot)$。**手算**（教学构造）：一组两条，长度 10（优势 +1）和 90（优势 $-1$）。样本级平均下，短样本每个 token 权重 $1/(2\times10)=0.05$，长样本 $1/(2\times90)\approx0.0056$；token 级下都是 $1/100=0.01$。论文的动机是：样本级平均让长回答中每个 token 的贡献变小，而过长样本常带有乱码和重复，得不到足够惩罚。Agent 里失败轨迹往往更长（搜满上限、反复调用），token 级损失能让这些坏模式受到相应的惩罚。注意 $\lvert o_i\rvert$ 应只数 `loss_mask=1` 的 token，否则观测长度会混进权重（verl 的 `loss_agg_mode=token-mean` 即此类聚合，见预备篇第 8 节）。

**④ 超长奖励整形**（§3.4）。先做“超长过滤”：被截断的样本不计损失。再加软惩罚，$L_{\max}=20480$、$L_{\text{cache}}=4096$：

$$
R_{\text{length}}(y)=\begin{cases}0,& \lvert y\rvert\le L_{\max}-L_{\text{cache}}\\ \dfrac{(L_{\max}-L_{\text{cache}})-\lvert y\rvert}{L_{\text{cache}}},& L_{\max}-L_{\text{cache}}<\lvert y\rvert\le L_{\max}\\ -1,& \lvert y\rvert>L_{\max}\end{cases}
$$

例：长度 18000 时 $(16384-18000)/4096\approx-0.395$。迁到 Agent 时要先定义 $\lvert y\rvert$ 数什么：只数模型生成的 token，还是连观测一起数（上下文窗口是被两者共同占满的）。DAPO 是单轮任务，没有回答这个问题；本文建议分别设上限：生成 token 用软惩罚，观测用截断（`max_tool_response_length`），轮数用硬上限。

**边界。** DAPO 的数字来自 32B 数学推理；Table 1 是逐项叠加，后加的模块增益依赖前面的模块，不能读成每项的独立贡献。

## 7. ReTool：代码解释器作为工具

ReTool（Feng et al., arXiv 2504.11536）在 Qwen2.5-32B-Instruct 上先用带代码的推理轨迹做冷启动 SFT，再用 PPO（verl）训练。rollout 中模型写 `<code>…</code>`，沙箱执行后把结果放进 `<interpreter>…</interpreter>` 拼回上下文；解释器输出在损失中被掩掉，和 Search-R1 的检索掩码同理。奖励只有答案正确性 $\pm1$，KL 系数 0，最大长度 16384，学习率 1e-6，batch 512。沙箱是异步的，用工作池做负载均衡。摘要报告 AIME 上 400 步达到 67%，纯文本 RL 基线 1080 步只有 40%。论文分析中，代码使用比例和代码行数随训练上升，调用时机提前，还出现了未经监督的代码自我纠错（看到报错后补上未定义的函数）。

它说明的一点是：**不给工具专门奖励**，只要工具真的有用，结果奖励也能把工具使用学出来；前提是冷启动让模型至少会写合法的代码块。

## 8. 环境与 rollout 工程

以下是本文的工程分析，不是某篇论文的结论。

| 问题 | 做法 |
|---|---|
| 工具慢且时延长尾 | 异步执行 + 工作池（ReTool）；超时当作一条观测返回，而不是让整个 batch 挂起 |
| 工具失败 | 错误信息作为观测拼回，让策略学会重试或换工具；记录失败率曲线 |
| 轨迹不终止 | 最大轮数、最大生成长度、观测截断三重上限；触顶比例单独监控 |
| 环境不确定 | 同一组的 $G$ 条轨迹应面对相同的初始状态与环境版本，否则组内差异混入环境噪声 |
| 成本 | 每步工具调用上界 = 题数 × $G$ × 最大轮数；动态采样会再乘上过采样倍数 |
| 可复现 | 固定随机种子、缓存工具返回（搜索结果、网页快照），评测时使用同一份缓存 |

## 9. 面试常问

**轨迹级优势有什么问题，怎样做到轮级？** 同一个优势广播到所有轮，坏的中间动作在成功轨迹里也被加强。做轮级有三条路：设计轮级奖励再算 reward-to-go；训练轮级或 token 级 critic（PPO/GAE）；不用 critic，按相同状态分组做相对比较（GiGPO）。前两者分别带来奖励投机和价值估计误差，后者要求状态能精确重复。

**格式奖励给多大？** 让它足以让解析成功率在早期快速达到很高，又明显小于正确性的量纲。ToolRL 的消融表明正确性放大到 $[-3,3]$、格式 $\{0,1\}$ 优于两者等量纲。训练中分项监控，格式分饱和后它就只剩约束作用。

**PRM 和 ORM 怎么选？** ORM 便宜、难投机，但稀疏；PRM 给中间信号，在 best-of-N 重排上明显更好（78.2% vs 72.4%），但标注贵、步难定义、学出来的 PRM 会被投机（DeepSeek-R1 §4.2）。Agent 里优先用规则化的轮级信号，学习型 PRM 先过离线重排关再进 RL。

**多轮 RL 训练塌了怎么查？** 看组内奖励标准差和熵是否先于奖励均值下降，看梯度范数有无尖峰（RAGEN）。对策：过滤零方差组或低方差组、Clip-Higher、更新鲜的 rollout、更多样的初始状态；必要时加 critic。

**DAPO 哪项对 Agent 最关键？** 若题目难度分布宽，动态采样（或训练前按 pass@G 筛题）直接决定有效 batch；若轨迹长短差异大，token 级损失决定长失败轨迹是否被惩罚。两者都要在只数生成 token 的前提下实现。
