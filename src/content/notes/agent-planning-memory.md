单次工具调用之后，下一个问题是：**一个要走二三十步的任务，模型怎样知道下一步该做什么，又怎样记住前面做过什么？** 这一篇分两半。前一半讲规划：ReAct、先规划再执行、反思这几种控制结构的差别和失败模式。后一半讲记忆：上下文窗口里放什么、放不下时怎样压缩、跨会话的信息怎样存和取。工具调用的协议见 [工具调用](/notes/agent-tool-calling/)，用强化学习训练这些行为见 [Agent RL 进阶](/notes/agent-rl-advanced/)。

阅读入口：[Agent 总览](/notes/agent-guide/)。数值算例为教学构造。

## 1. 为什么多步任务难

假设每一步做对的概率是 $p$，步骤之间相互独立，$n$ 步全对的概率是 $p^n$。$p=0.95$ 时，10 步只剩 $0.95^{10}\approx0.60$，20 步只剩 $0.36$。真实情况比这更糟也更好：更糟是因为错误会**传导**（一个错的中间结果让后面每一步都建立在错误前提上）；更好是因为好的系统能**发现并纠正**错误。规划和记忆的设计，本质上都是在提高单步正确率 $p$，或者给系统加上纠错的机会。

三种典型失败：

- **迷路**：做着做着忘了最初的目标，或在子任务里打转；
- **重复**：同一个工具用同样的参数反复调用，因为不记得已经调过；
- **过早结束**：没有验证就宣布完成，或者遇到一次失败就放弃。

## 2. ReAct：边想边做

ReAct（Yao et al., arXiv 2210.03629）让模型交替输出三种内容：

```
Thought: 我需要先知道这部电影的导演是谁
Action: search["奥本海默 导演"]
Observation: 克里斯托弗·诺兰……
Thought: 现在查诺兰的出生年份
Action: search["克里斯托弗·诺兰 出生"]
Observation: 1970 年 7 月 30 日……
Thought: 信息足够了
Action: finish["1970"]
```

**为什么有效。** Thought 让模型把“下一步做什么、为什么”写出来，相当于把规划分散到每一步；Observation 让每一步都基于真实环境的反馈，而不是凭空推理。论文对比了只推理（CoT，容易编造事实）和只行动（不写 Thought，容易做无目的的动作），二者结合在 HotpotQA、ALFWorld 等任务上更好。

**失败模式。** ① 每一步只看局部，缺乏全局计划，长任务里容易迷路。② Thought 可能和 Action 不一致：写着“查出生年份”，实际调用的参数却是别的。③ 上下文随步数线性增长，几十步后旧的观察挤占窗口。现在的原生函数调用接口本质上就是 ReAct：模型的文字回复对应 Thought，`tool_calls` 对应 Action，`tool` 消息对应 Observation。

## 3. 先规划再执行

**Plan-and-Execute**：先让模型一次性写出完整计划（步骤列表），再逐步执行，每步执行完可以修订剩余计划。代表工作有 Plan-and-Solve（arXiv 2305.04091）和 LLMCompiler（arXiv 2312.04511，把计划写成依赖图，无依赖的步骤并行执行）。

| | ReAct | 先规划再执行 |
|---|---|---|
| 全局视野 | 弱，每步只看下一步 | 强，开始就有完整步骤 |
| 对意外的适应 | 强，每步都基于最新观察 | 弱，需要显式的“重新规划”触发 |
| 并行 | 难 | 计划成图后可以并行 |
| 调用规划者的次数 | 每步一次 | 开始一次加若干次修订，可以用强模型规划、弱模型执行 |

实际系统大多是混合：先写一个粗计划放在上下文里，执行时每步仍按 ReAct 方式根据观察决定细节，遇到计划假设被推翻（例如要找的文件不存在）时重新规划。**把计划写成一个可勾选的待办列表**、每完成一项更新一次，是一个简单有效的技巧：它同时解决了“迷路”（目标一直在上下文里）和“过早结束”（还有未勾选项）。

## 4. 反思：让失败变成下一次的输入

**Reflexion**（Shinn et al., arXiv 2303.11366）：一次尝试失败后（例如单测没过），让模型写一段自然语言的反思（“我忘了处理空列表的情况”），存进记忆，下一次尝试时放进上下文。论文称之为“语言强化学习”：不更新权重，用文字形式的反馈改进行为。

**反思什么时候有用。** 关键是**有可靠的外部信号**：单测通过与否、环境返回的成功标志、可执行的检查。有了它，反思是在分析具体的失败原因。没有外部信号时，让模型“检查一下自己的答案”往往效果有限：模型在第一次生成时犯的错，在自我检查时多半也看不出来，甚至可能把对的改成错的。Huang et al. 的“Large Language Models Cannot Self-Correct Reasoning Yet”（arXiv 2310.01798）专门讨论了这一点：没有外部反馈的自我纠错在推理任务上常常没有提升。

**手算：带检查的重试**（教学构造）。单次尝试成功率 0.6；有一个检查器，能发现 90% 的失败（10% 的失败被误判为成功）。最多尝试 3 次。每次尝试失败且被发现的概率是 $0.4\times0.9=0.36$，只有这种情况才会重试。最终成功率 $=0.6+0.36\times0.6+0.36^2\times0.6=0.6+0.216+0.078=0.894$。如果检查器只能发现 50% 的失败，则是 $0.6+0.2\times0.6+0.2^2\times0.6=0.744$。重试的收益几乎完全取决于检查器的召回率：**先投资检查器，再谈反思**。

## 5. 记忆的三层

| 层 | 放在哪 | 容量 | 生命周期 | 例子 |
|---|---|---|---|---|
| 短期 | 上下文窗口 | 窗口大小 | 一次请求 | 当前对话、最近的工具结果 |
| 工作 | 上下文里的结构化区域，或外部草稿文件 | 小 | 一个任务 | 待办列表、已确认的事实、中间结论 |
| 长期 | 外部存储（向量库、数据库、文件） | 不限 | 跨任务、跨会话 | 用户偏好、过去任务的经验、知识库 |

短期记忆是模型唯一能“直接看到”的东西。工作和长期记忆都必须在合适的时候被**读回**上下文才有用，所以记忆系统的核心问题是两个：**写什么**（什么值得保存）和**读什么**（当前步骤需要哪些）。

## 6. 长期记忆怎样取：一个打分算例

Generative Agents（Park et al., arXiv 2304.03442）给每条记忆打三个分，相加后取最高的几条：

- **时近性**：距离上次被访问的时间按指数衰减，论文用每小时衰减因子 0.995；
- **重要性**：写入时让模型给这条记忆打 1–10 分（“吃早饭”是 1，“分手”是 10）；
- **相关性**：记忆与当前查询的 embedding 余弦相似度。

三个分数各自在候选集合内做 min-max 归一化到 $[0,1]$，论文中权重都取 1。

**手算**（教学构造）。三条候选记忆：

| 记忆 | 距上次访问 | 重要性 | 相关性 | 时近性 $0.995^h$ |
|---|---:|---:|---:|---:|
| m1 | 2 小时 | 8 | 0.40 | 0.990 |
| m2 | 30 小时 | 3 | 0.85 | 0.860 |
| m3 | 100 小时 | 9 | 0.60 | 0.606 |

归一化后（时近性、重要性、相关性）：m1 = (1.000, 0.833, 0.000)，总分 1.833；m2 = (0.663, 0.000, 1.000)，总分 1.663；m3 = (0.000, 1.000, 0.444)，总分 1.444。**最相关的 m2 输给了最不相关的 m1**，因为 m1 又新又重要。如果把相关性的权重调成 2，总分变成 1.833、2.663、1.888，m2 胜出。

这个例子说明两点。① min-max 归一化会把很小的原始差距放大成 0 和 1 的差距：m1 和 m2 的时近性只差 0.13，归一化后差 0.34。候选只有两三条时尤其失真。② 权重是任务相关的超参数：社交模拟里“最近发生的重要事情”很关键；问答助手里相关性应该占主导。上线前要用一组标注过“应该取回哪条”的查询来调权重。

## 7. 上下文快满了怎么办

**截断**：丢掉最早的消息。最简单，但可能把任务目标也丢掉。至少要保证系统提示、原始任务和当前计划永远不被截断。

**压缩（摘要）**：历史超过阈值时，让模型把旧的部分总结成一段摘要，替换原文。Anthropic 和 OpenAI 的长任务 Agent 产品都有类似的“compaction”机制。

**手算：压缩的频率**（教学构造）。窗口 32k token，系统提示加工具定义 3k，预留输出 4k，留给历史的是 25k。每步新增 1.5k。每次压缩后历史剩 3k 的摘要。

- 第一次压缩前能走 $\lfloor25\,000/1500\rfloor=16$ 步；
- 之后每轮能走 $\lfloor(25\,000-3000)/1500\rfloor=14$ 步；
- 一个 50 步的任务：16 → 压缩 → 30 → 压缩 → 44 → 压缩 → 50，共压缩 3 次。

每压缩一次，细节都会丢失一部分，而且摘要本身是模型生成的，可能遗漏或扭曲关键信息。三次压缩后，第 5 步看到的一个报错信息很可能已经不在了。

**外部化**：把信息写进文件而不是留在上下文里。例如 Agent 把调研结果写进 `notes.md`，需要时再读；把计划写进 `todo.md`，每步更新。压缩时只需要保留“文件在哪、里面大概有什么”。这比摘要更可控：文件内容不会因为压缩而失真，需要时可以完整读回。

**减少写入**：工具返回的大段内容（网页全文、日志）先截断或只保留相关部分再放进上下文。很多时候上下文被撑满不是因为步数多，而是因为单个观察太长。

**MemGPT**（arXiv 2310.08560）把这些做法系统化：把上下文比作内存、外部存储比作磁盘，让模型自己通过函数调用决定什么时候把信息换入换出。

## 8. 怎样判断规划和记忆有没有起作用

不能只看最终成功率，要看过程指标：

- **重复调用率**：同一工具同一参数在一个任务里被调用多次的比例，高说明短期记忆失效；
- **目标偏离**：抽查长任务的后半段，模型的行动是否还服务于原始目标；
- **计划完成度**：计划里的步骤有多少被真正执行并验证；
- **压缩前后对比**：同一任务在大窗口不压缩和小窗口压缩两种设置下的成功率差，衡量压缩带来的损失；
- **记忆检索准确率**：对一组标注过的查询，取回的记忆里有没有该取的那条。

## 9. 面试常问

**ReAct 和 CoT 有什么区别？** CoT 只在模型内部推理，容易编造事实；ReAct 在推理之间插入真实的工具调用与观察，每一步都基于环境反馈。原生函数调用接口本质上就是 ReAct。

**先规划再执行和 ReAct 怎么选？** 步骤可预知、需要并行时先规划；环境不确定、每步结果会改变后续决策时用 ReAct。实际常用混合：粗计划加逐步执行，假设被推翻时重新规划。

**自我反思一定有用吗？** 有外部可靠信号（单测、环境反馈）时有用；没有时，模型往往发现不了自己的错误，甚至把对的改错。重试的收益取决于检查器的召回率。

**长期记忆怎样设计？** 写入时决定存什么（去重、打重要性分），读取时按相关性、时近性、重要性打分取 top-$k$；权重要在标注数据上调；注意 min-max 归一化在候选少时失真。还要处理过时信息的更新与删除。

**上下文窗口不够怎么办？** 截断（保护系统提示和任务目标）、压缩成摘要、外部化到文件、减少单次观察的长度。压缩会丢细节，外部化更可控。
